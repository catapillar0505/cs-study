# 프라이빗 레지스트리 인증

> 한 줄 요약
> **비밀값을 저장해 두는 대신, 필요할 때 그 자리에서 발급받는 쪽이 구조적으로 안전하다.**

## 문제 상황

컨테이너 이미지는 레지스트리에 올라가 있고, 노드는 파드를 띄울 때 거기서 이미지를 받아온다. **프라이빗 레지스트리는 인증이 필요하다.** 관리형 클러스터는 이 인증이 자동으로 연결되어 있지만, 직접 구축한 클러스터에는 그 연결이 없어 **이미지를 받지 못한다.**

## 방법 1 — Secret에 자격증명 저장 (`imagePullSecrets`)

토큰을 미리 받아 클러스터에 Secret으로 저장해 두고, 파드가 그것을 참조한다.

```yaml
spec:
  imagePullSecrets:
    - name: registry-cred
```

**한계**
- 토큰에 **유효기간**이 있으면(예: 12시간) 갱신 작업을 따로 돌려야 하고, **만료 타이밍에 배포가 걸리면 실패**한다
- 자격증명이 **클러스터 안에 계속 저장된 상태**로 남는다
- 네임스페이스마다 Secret을 만들어야 한다

## 방법 2 — Credential Provider (그때그때 발급)

토큰을 저장하지 않고, **이미지를 받아올 때마다 그 자리에서 발급받는다.**

```
① kubelet이 이미지를 받아오려 한다
② 이미지 주소가 등록된 레지스트리면, 미리 지정해 둔 자격증명 플러그인을 호출한다
③ 플러그인이 노드에 붙은 권한(인스턴스 역할 등)으로 토큰을 발급받는다
④ 토큰을 kubelet에 돌려주고, kubelet이 그것으로 이미지를 받는다
```

**핵심은 ③이다.** 노드 자체에 권한이 붙어 있어서 **어딘가에 비밀값을 적어둘 필요가 없다.** 토큰은 유효기간만큼 캐시되고 알아서 다시 발급된다.

| | Secret 저장 | Credential Provider |
|---|---|---|
| 자격증명 위치 | 클러스터 안에 저장됨 | **저장하지 않음** |
| 만료 처리 | 갱신 작업 필요 | 자동 재발급 |
| 설정 위치 | 네임스페이스마다 | 노드(kubelet) 한 번 |

## 곁들여 알아둘 것 — 메타데이터 서비스 v1 / v2

노드에 붙은 권한을 조회할 때 쓰는 메타데이터 엔드포인트에는 두 방식이 있다.

- **v1**: 요청 한 번이면 자격증명이 그대로 나온다.
- **v2**: **토큰을 먼저 받아야** 조회가 된다.

v1이 위험한 이유는 **SSRF** 때문이다. 애플리케이션에 "이 주소를 대신 조회해 줘"라고 시킬 수 있는 취약점이 있으면, 외부에서 그 자격증명을 그대로 빼갈 수 있다. **v2는 사전 토큰 발급(PUT)이 필요해 단순한 우회로는 뚫리지 않는다.**

## 운영 팁

- 플러그인 바이너리의 **다운로드 주소를 설정에 하드코딩하지 않는다.** 주소가 바뀌면 설치가 통째로 실패한다 — 변수로 빼두면 한 줄만 고치면 된다.
