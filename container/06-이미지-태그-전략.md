# 컨테이너 이미지 태그 전략

> 한 줄 요약
> **이미지 하나가 코드 한 시점과 일대일로 대응해야 한다.**

## `latest`가 위험한 이유

`latest` 같은 움직이는 태그를 쓰면 **같은 이름인데 내용이 계속 바뀐다.** 그러면

- **장애가 났을 때 지금 돌고 있는 게 어느 코드인지 알 수 없고**
- **롤백하려 해도 되돌릴 대상이 특정되지 않으며**
- 노드마다 받아둔 캐시가 달라 **같은 태그인데 서로 다른 이미지가 도는** 상황이 생긴다

## 커밋 해시를 태그로

```
myapp:a3f9c21          # git 커밋 해시
myapp:2024.08.27-a3f9c21
```

이미지가 코드 한 시점과 일대일 대응된다. 문제가 생기면 그 커밋을 보면 되고, **이전 태그로 되돌리면 정확히 그 상태로 간다.**

## 함께 쓰는 규칙

| 규칙 | 이유 |
|---|---|
| `imagePullPolicy: IfNotPresent` + 불변 태그 | 태그가 불변이면 매번 받아올 이유가 없다 |
| 레지스트리에서 **태그 덮어쓰기 금지** 설정 | 같은 태그로 다른 내용이 올라가는 것을 원천 차단 |
| 다이제스트(`@sha256:...`) 고정 | 가장 엄격. 태그마저 못 믿을 때 |
| `latest`는 **개발 편의용으로만** | 배포 매니페스트에는 쓰지 않는다 |

**되돌릴 수 있게 만드는 것**이 태그 전략의 목적이다.
