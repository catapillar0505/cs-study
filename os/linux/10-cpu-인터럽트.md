# CPU 인터럽트

CPU가 하던 일을 잠시 멈추고 급한 일을 먼저 처리하도록 알리는 신호입니다.

왜 필요하냐면, 외부 장치가 언제 준비될지 CPU가 모르기 때문입니다. 네트워크 카드에 패킷이 언제 도착할지, 키보드를 언제 누를지 알 수 없습니다.

인터럽트가 없다면 CPU가 계속 물어봐야 합니다. 패킷 왔어, 아직 안 왔어, 지금은 왔어 하는 식으로요. 이걸 폴링이라고 하는데 CPU를 낭비합니다.

인터럽트 방식은 반대입니다. CPU는 자기 일을 하고 있다가, 장치가 준비되면 신호를 보냅니다. CPU는 그때 하던 일의 상태를 저장하고, 인터럽트 처리 루틴으로 점프해서 처리하고, 다시 원래 일로 돌아옵니다.

문제는 이 전환에 비용이 든다는 것입니다. 상태 저장하고 복원하는 것 자체가 시간입니다. 패킷 하나에 인터럽트 하나가 걸린다고 하면, 초당 수십만 패킷이 오는 환경에서는 CPU가 인터럽트 처리만 하다가 끝날 수 있습니다.

그래서 MTU를 키우면 왜 좋은지가 여기서 나옵니다. 같은 데이터를 패킷 6분의 1로 보내면 인터럽트도 6분의 1이 됩니다. 그만큼 CPU가 실제 일을 할 시간이 늘어납니다.

요즘 NIC은 인터럽트 코얼레싱이라는 기능도 씁니다. 패킷 하나마다 인터럽트를 걸지 않고 몇 개 모아서 한 번에 거는 방식입니다.
