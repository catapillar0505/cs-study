# 파일시스템 구조와 마운트

## 리눅스 디렉토리 구조 (FHS)
| 디렉토리 | 역할 |
|---|---|
| `/boot` | 커널, GRUB 설정, initrd 등 부팅 파일 |
| `/bin` | 기본 명령어(`ls`, `cp`, `cat`) |
| `/sbin` | 시스템 관리 명령어(root용) |
| `/etc` | 시스템 설정 파일 |
| `/home` | 각 사용자 홈 디렉토리 |
| `/root` | root 전용 홈 디렉토리 |
| `/var` | 자주 변하는 데이터(로그 `/var/log` 등) |
| `/tmp` | 임시 파일 (Sticky Bit `1777`) |
| `/usr` | 설치된 프로그램·라이브러리 대부분 |
| `/lib` | 시스템 필수 라이브러리 |
| `/dev` | 장치(device) 파일 — `/dev/sda1` 등 |
| `/proc` | 커널이 실시간 생성하는 가상 파일시스템(프로세스 정보) |
| `/sys` | 커널·하드웨어 상태 가상 파일시스템 |
| `/mnt`, `/media` | 외부 저장장치 마운트 위치 |
| `/opt` | 서드파티 수동 설치 소프트웨어 |

- **`/dev`, `/proc`, `/sys`는 디스크 저장이 아니라 커널이 메모리에 실시간 생성**(재부팅 시 새로 생성).
- 그 외(`/etc`, `/home` 등)는 실제 디스크에 저장, 재부팅해도 유지.

## 장치 이름 규칙
```
/dev/sda1
     │││└─ 파티션 번호
     ││└── 몇 번째 디스크인지 (a, b, c...)
     │└─── Disk
     └──── SCSI (Small Computer System Interface)
```
- `/dev/sda` = 첫 번째 디스크, `/dev/sdb` = 두 번째 디스크.
- `/dev/sda1` = sda 디스크의 1번 파티션.
- NVMe SSD는 `/dev/nvme0n1` 같은 다른 규칙 사용.

## 마운트(Mount) — 핵심 개념
- **마운트 = 저장장치의 파일시스템을 특정 디렉토리 경로에 연결해 접근 가능하게 만드는 것.**
- **복사가 아님!** 파일이 옮겨오는 게 아니라 "접근 경로만 이어붙이는 것".
```bash
sudo mount /dev/sdb1 /mnt/usb   # USB를 /mnt/usb에 연결
sudo umount /mnt/usb            # 연결 해제(파일은 USB에 그대로)
```
- 루트(`/`)조차도 사실은 특정 디스크 파티션이 `/`에 마운트된 것.
- `/mnt/usb/photo.jpg`를 수정하면 → USB 안의 실제 파일이 수정됨(사본이 아님).

## 드라이버 vs 마운트 (순서)
```
1. USB 꽂음
2. 커널이 장치 인식 + 드라이버가 하드웨어와 통신 (드라이버 처리)
3. 커널이 /dev/sdb1로 노출
4. mount로 /dev/sdb1을 /mnt/usb에 연결 (마운트)
```
- **드라이버**: "이 하드웨어와 어떻게 통신하는지 아는 번역기 코드".
- **마운트**: 통신 가능한 상태에서 "파일시스템을 디렉토리에 끼워넣는 것".

## 디스크 → 파일시스템 → 마운트 → 디렉토리 (전체 그림)
| 용어 | 의미 |
|---|---|
| 디스크 파티션 | 물리적 저장 공간(raw 데이터) |
| 파일시스템 | 그 공간을 파일/폴더로 정리하는 **형식/규칙**(ext4, NTFS 등) |
| 마운트 | 정리된 파일시스템을 디렉토리 경로에 연결 |
| 디렉토리 | 터미널에서 `ls`, `cd`로 오가는 경로 |

- 커널이 하드웨어 raw 데이터를 "파일/폴더"로 **번역**하고, 쉘/터미널은 그 결과에 접근하는 창구.

## LVM (Logical Volume Manager)
파티션을 유연하게 관리하기 위한 중간 계층.
```
물리 파티션(PV) → 볼륨 그룹(VG) → 논리 볼륨(LV)
```
| 단계 | 역할 |
|---|---|
| PV (Physical Volume) | 실제 파티션을 LVM 원재료로 등록 |
| VG (Volume Group) | 여러 PV를 묶은 "용량 풀" |
| LV (Logical Volume) | 풀에서 잘라낸 가상 파티션 (실제 `/`에 마운트) |
- 장점: 디스크 추가 시 유연한 용량 확장, 스냅샷 등.

## 디스크/메모리 확인 명령어
```bash
df -h        # Disk Free — 마운트된 파일시스템 용량/사용량
du -sh 폴더   # Disk Usage — 특정 폴더/파일 용량
free -h      # 메모리(RAM) 사용 현황
lsblk        # list block device — 블록 장치(디스크/파티션) 트리 구조
fdisk -l     # 파티션 테이블 조회
```

- **df vs free**: df는 **디스크(저장장치)**, free는 **메모리(RAM)**. 완전히 다른 하드웨어.
  - 디스크 = 영구 저장(전원 꺼도 유지), 메모리 = 임시 작업 공간(전원 끄면 사라짐).
- **df vs du**: df는 파일시스템 전체, du는 특정 파일/폴더.
- **fdisk**: `-l`은 조회만. 생성/삭제는 옵션 없이 `fdisk /dev/sda`로 대화형 모드 진입 후 `n`/`d`/`w` 등 사용.

## /etc/fstab
- **Filesystem Table** — 부팅 시 자동 마운트할 파일시스템 목록 설정 파일.
- 잘못 수정하면 **부팅 불능**이 될 수 있어 수정 전 백업 필수:
```bash
sudo cp /etc/fstab /etc/fstab.bak
```
