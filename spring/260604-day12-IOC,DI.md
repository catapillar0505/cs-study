# **DI**

**만들어진 빈을 찾아서 가지고 온다 (새로 만들어 사용하지 않음)**

실무에서는 필드 주입을 쓰지 않고, 생성자 주입 사용

| 단계 | 생성자 주입 | 필드 주입 |
|------|------------|----------|
| 1 | 의존성 빈 탐색 | 생성자 호출 (파라미터 없음) |
| 2 | 생성자 파라미터로 의존성 전달 및 할당 = 필드 주입 | 리플렉션으로 필드에 주입 |
| 3 | 객체 완성 + 빈 등록 | 빈 등록 |

> 리플렉션 = 객체 생성 이후에 private도 무시하고 외부에서 값을 꽂아넣는 방식

### <생성자 주입을 쓰는 이유>

## 1. 불변성 보장 (`final`)

- final 키워드는 생성자에서만 초기화 가능하다는 뜻이므로
- 필드에 `final` 선언 가능 → 객체 생성 후 의존성 교체 불가
- 멀티스레드 환경에서 안전

> 필드 주입(`@Autowired`)은 리플렉션으로 나중에 값을 넣기 때문에 `final` 불가
> 리플렉션은 "생성자에서만 초기화"라는 final 규칙과 충돌해서 함께 쓸 수 없음.

## 2. NPE 방지
OrderRepository 빈 = 의존성 빈

생성자 주입 = 의존성 빈 탐색 후 객체 생성
              → 찾으면: 생성자 호출(객체 생성 + 주입 동시) → 빈 등록
              → 못 찾으면: 생성자 호출 자체 안 함 (객체 생성 X, 빈 등록 X)

필드 주입   = 객체 생성 후 의존성 빈 탐색
              → 찾으면: 필드에 리플렉션으로 주입 → 빈 등록
              → 못 찾으면: 예외 발생 (기본값)

생성자 주입 실패 = 객체가 없다 → NPE 발생 경로 자체가 없음
필드 주입 실패   = 객체는 있다 → null 필드를 가진 채로 힙에 존재
                               → 접근하면 NPE 발생 가능성 있음

> **한 줄 요약:** 생성자 주입 = `final` + 조기 감지 + NPE 방지 + 쉬운 테스트
---
@RequiredArgsConstructor  →  Lombok이 생성자 코드 생성

스프링                    →  그 생성자를 보고 의존성 주입



필드 선언시 final 키워드를 추가합니다 -> final을 통해 객체 NPE 방지, 객체 불변성 유지, 순환참조 방지

final 붙이면 필드주입, 세터주입 불가능. final을 초기화할 수 있는 것은 생성자 주입뿐이다.


@Autowired는 "이 생성자(또는 필드)를 주입에 써라" 고 명시적으로 알려주는 마커야
