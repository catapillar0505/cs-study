# Restful API
Representational State Transfer
= 상태 전송 재정의
= 자원 -> 경로(URI)로 구분
= 자원의 상태(행위) -> HTTP 메서드로 구분

ful
= 해당 방식으로 지키려고 노력하였음
= 표준 그 자체인 것은 아님

### CSR 아키텍처에서 서버의 역할

- 서버는 "화면"이 아닌, 오직 "순수한 데이터(JSON)"만 정제해서 클라이언트에게 제공하는 독립적인 역할을 수행함

- 이와 같이 동작하는 서버를 흔히 REST API 서버라고 함


<데이터 보내는 법>
[1] ?id=123 -> 쿼리스트링으로 데이터 보내기
1) HttpServeletRequest
2) @RequestParam
3) 커맨드 객체

[2] /users/42 -> 경로변수로 데이터 보내기
- @PathVariable
경로 변수 추출은 Spring MVC 전용 기능이라 @PathVariable 없이는 접근 불가

[3] DTO -> 요청 본문에 포함 시켜 보내기 
주소에 노출하지 않는 방법 
    JSON/XML         →  @RequestBody
    HTML Form        →  커맨드 객체 (@ModelAttribute)

#### 멱등성
같은 요청을 한번했을 때와 요청 100번했을 때 결과가 같은 것

**< 멱등성 있는 것>**
- 조회, 수정, 삭제
- 테라폼/앤서블 멱등성 = "몇 번 실행해도 결과는 항상 선언한 상태 그대로"
  - "현재 상태 vs 원하는 상태" 비교를 통해 차이만 적용

**< 멱등성 없는 것 ( 여러번 하면 안되는 것) >**
- 등록 서비스
- 결제 서비스
