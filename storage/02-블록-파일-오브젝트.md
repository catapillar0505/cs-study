# 블록 · 파일 · 오브젝트 스토리지

저장하는 단위와 접근 방법이 다릅니다. 파일 스토리지까지 셋으로 나눠 보는 게 이해하기 좋습니다.

블록 스토리지는 디스크를 고정 크기 조각으로 나눠서 다룹니다. 조각 하나가 블록이고 보통 4킬로바이트입니다. 접근할 때 몇 번 블록을 읽어라, 몇 번 블록에 써라 하는 식입니다. 파일이라는 개념이 여기엔 없습니다.

파일이라는 개념은 그 위에 파일시스템이 얹혀야 생깁니다. ext4나 XFS 같은 파일시스템이 이 파일의 이 위치는 몇 번 블록이라는 지도를 들고 있습니다.

블록 스토리지는 가장 빠르고 세밀합니다. 파일 중간의 4킬로바이트만 고쳐 쓰는 것도 됩니다. 그래서 데이터베이스나 VM 디스크처럼 성능이 중요하고 부분 수정이 잦은 데 씁니다. AWS의 EBS, Ceph의 RBD가 여기 해당합니다.

파일 스토리지는 우리가 아는 폴더와 파일 구조입니다. 여러 서버가 동시에 마운트해서 공유할 수 있습니다. NAS와 CephFS가 여기 해당합니다.

오브젝트 스토리지는 데이터를 통째로 하나의 덩어리로 다룹니다. 그 덩어리가 오브젝트입니다. 폴더 구조도 없이 그냥 평평한 공간에 이름표를 붙여서 넣어둡니다.

가장 큰 차이는 접근 방법입니다. 오브젝트 스토리지는 HTTP로 접근합니다. PUT 요청으로 올리고 GET 요청으로 받습니다. 마운트하는 게 아니라 웹 API를 호출하는 것입니다.

그리고 부분 수정이 안 됩니다. 100메가짜리 파일에서 1바이트만 바꾸려면 100메가 전체를 다시 올려야 합니다. 대신 용량 확장이 쉽고 저렴하며, 데이터를 여러 서버에 복제해 두기 좋습니다.

그래서 용도가 갈립니다. 사진, 동영상, 백업, 로그, 머신러닝 학습 데이터셋처럼 한 번 쓰고 여러 번 읽는 데이터에 오브젝트 스토리지가 맞습니다. AWS의 S3, Ceph의 RGW가 여기 해당합니다.

그래서 실무에서는 VM 디스크나 상태 저장 볼륨은 블록으로, 모델 가중치나 이미지·로그 같은 대용량 파일은 오브젝트로 나눠 씁니다.
