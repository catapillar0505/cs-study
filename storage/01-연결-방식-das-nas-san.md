# 스토리지 연결 방식 — DAS · NAS · SAN

서버가 저장장치를 쓰는 방식이 크게 세 가지입니다. 이걸 알아야 SAN이 뭔지 이해가 됩니다.

첫째는 DAS입니다. 서버에 디스크를 직접 꽂는 방식입니다. 노트북에 SSD가 들어 있는 것과 같습니다. 가장 빠르지만 그 서버만 쓸 수 있고, 서버가 죽으면 데이터에 접근할 수 없습니다.

둘째는 NAS입니다. 네트워크로 연결된 파일 서버입니다. 회사 공유 폴더를 생각하면 됩니다. 여러 서버가 같은 폴더를 동시에 마운트해서 씁니다. 파일 단위로 접근하고 일반 이더넷 네트워크를 씁니다. 쉽고 저렴하지만 성능은 상대적으로 낮습니다.

셋째가 SAN입니다. 이건 따로 설명하겠습니다.


## 2-2. SAN


SAN은 Storage Area Network의 약자로, 스토리지 전용 네트워크입니다.

핵심은 이겁니다. 서버가 스토리지를 네트워크 너머에 두고 쓰는데, 서버 입장에서는 마치 자기 몸에 붙은 디스크처럼 보인다는 것입니다.

NAS와 결정적으로 다른 점이 여기입니다. NAS는 서버가 파일 서버에 접속해서 파일을 요청합니다. 파일이라는 개념이 있습니다. SAN은 블록 단위로 접근합니다. 서버는 그냥 몇 번 블록을 읽어달라고 요청하고, 운영체제 입장에서는 로컬 디스크와 구분이 안 됩니다. 그래서 파일시스템도 서버가 직접 만들어 붙입니다.

SAN은 보통 파이버 채널이라는 전용 케이블과 전용 스위치를 씁니다. 이더넷과 별개인 네트워크입니다. 왜 따로 두냐면, 일반 네트워크 트래픽과 섞이면 디스크 응답 시간이 불안정해지기 때문입니다. 디스크는 지연에 아주 민감합니다.

여기서 SAN 스위치가 나옵니다. 서버들과 스토리지 장비를 연결하는 전용 스위치입니다. 존(zone)이라는 개념으로 어느 서버가 어느 스토리지에 접근할 수 있는지를 제어합니다.

SAN을 쓰면 얻는 게 큽니다. 스토리지를 한군데 모아 관리할 수 있고, 서버가 죽어도 데이터는 스토리지에 남아 있어서 다른 서버에 붙이면 됩니다. 가상화에서 라이브 마이그레이션이 가능한 것도 이 구조 덕분입니다. VM 디스크가 공유 스토리지에 있으니까 VM을 다른 호스트로 옮겨도 디스크는 그대로 접근됩니다.

요즘은 iSCSI라고 해서 일반 이더넷 위에서 SAN처럼 블록 접근을 하는 방식도 많이 씁니다. 전용 장비가 없어도 되니 저렴하지만 성능은 파이버 채널보다 떨어집니다.
