# Security Group과 NACL

## 9. 패킷과 세션

> **한 줄 요약**
> **패킷은 편지 한 통, 세션은 주고받은 대화 전체.**

### 비유

친구에게 편지를 보내고 답장을 받았어요.

- **편지 한 통 한 통** = 패킷 (가는 편지, 오는 편지)
- **주고받은 대화 전체** = 세션

**"내가 먼저 편지를 보낸 대화"** 라고 하면, 그 안엔 **내 편지도 있고 친구 답장도 있죠.**

### 그래서 헷갈립니다

**"인바운드 SSH"** = 외부에서 **먼저 시작한** 대화라는 뜻이에요.
그 안에는 들어오는 패킷도 있고 **나가는 패킷(응답)도 있습니다.**

SSH 접속 하나를 펼치면 이래요.

| 순서 | 내용 | 방향 |
|---|---|---|
| 1 | "안녕하세요?" | **들어옴** |
| 2 | "네 안녕하세요" | **나감** |
| 3 | "접속할게요" | 들어옴 |
| 4~ | 대화 계속 | 왔다갔다 |

이 전부가 **"인바운드 세션 1개"** 입니다. 1번이 밖에서 왔다는 이유 하나로요.

### 왜 이걸 알아야 하나

AWS 구성 요소마다 **보는 단위가 다르기 때문**입니다.

| | 뭘 보나 | 결과 |
|---|---|---|
| **보안 그룹** | **세션(대화 전체)** | 들어오는 것만 열면 답장은 자동으로 나감 |
| **NACL** | **패킷 한 통** | 답장도 따로 열어줘야 함 |
| **이정표** | **패킷 한 통** | 답장도 다시 길을 찾음 |

## 10. Security Group과 NACL

> **한 줄 요약**
> **보안 그룹은 얼굴을 기억하는 경비원, NACL은 매번 새로 검사하는 검문소.**

### 비유

**보안 그룹 = 우리 집 현관 경비원**
"아까 들어온 손님이네" 하고 기억해요. 나갈 때 다시 안 물어봅니다.

**NACL = 동 입구 검문소**
기억을 전혀 못 해요. 들어올 때 검사하고, 나갈 때 **또 검사**합니다.

### 비교

| | **보안 그룹** | **NACL** |
|---|---|---|
| 어디에 | 집 현관 (서버 하나하나) | 동 입구 (서브넷 전체) |
| 기억력 | **있음** (Stateful) | **없음** (Stateless) |
| 답장 | 자동 통과 | **따로 열어야 함** |
| 규칙 | 허용만 | 허용 + 차단 |

### ⚠️ 여기서 다들 한 번은 당합니다

NACL에서 SSH를 열려고 이렇게 씁니다.

```
들어올 때: 22번 허용  ✓
나갈 때:   22번 허용  ✗ ← 틀림!
```

**답장은 22번으로 안 나가거든요.** 답장은 상대방이 쓰던 임시 번호(5만번대)로 갑니다.

```
나갈 때: 1024~65535 허용  ✓ 이게 맞음
```

보안 그룹은 이런 고민이 없어요. **기억하고 있으니까요.** 이게 Stateful과 Stateless의 실제 차이입니다.

### 실전 설정

```
22번  ← 내 IP만        (SSH는 나만 쓰니까)
443번 ← 전 세계        (사용자가 써야 하니까)
```

### 소스에 IP 대신 보안 그룹 쓰기 ★

**"이 IP에서 오면 허용"** 대신 **"이 그룹 소속이면 허용"** 이라고 적는 방법입니다.

| 방식 | 도어락에 뭐라고 등록? |
|---|---|
| **IP로 지정** | "**301호 사람**만 들어와" |
| **SG로 지정** | "**관리사무소 직원증** 있는 사람만 들어와" |

방 번호로 등록하면 그 사람이 이사 가면 끝이지만, **직원증으로 등록하면 담당자가 바뀌어도 그대로 통합니다.**

```
프라이빗 EC2의 보안 그룹 (인바운드)

22번   ← sg-bastion    (배스천을 단 서버면 허용)
8080번 ← sg-alb        (ALB를 단 놈이면 허용)
```

**왜 훨씬 나은가?**

① **IP가 바뀌어도 안 깨짐** — 배스천을 재시작하면 사설 IP가 바뀔 수 있는데, IP로 적었으면 그때마다 규칙을 고쳐야 합니다.

② **서버가 늘어나도 규칙은 한 줄** — Auto Scaling으로 2대 → 10대가 되면?

| | 규칙 몇 줄? |
|---|---|
| IP로 지정 | **10줄** (늘어날 때마다 추가) |
| SG로 지정 | **1줄** (끝) |

새로 뜨는 서버가 자동으로 그 SG를 달고 나오니 **아무것도 안 해도 됩니다.**

**주의할 점**

- **방향이 있습니다.** `A의 인바운드 ← sg-B`는 "B → A"만 허용. 반대는 따로 열어야 함
- **같은 VPC 안에서만** 됩니다 (VPC 피어링 시 예외)
