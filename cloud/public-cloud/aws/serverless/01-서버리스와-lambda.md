# 서버리스와 Lambda

## 한 줄로

**서버가 없는 게 아니라, 서버를 내가 관리하지 않는 것.** 코드(함수)만 올려두면 **요청이 올 때만** AWS가 실행 환경을 띄워서 돌려주고, **돈도 실행한 만큼만** 낸다.

## 문제부터 — EC2로 API 하나 띄우려면

```
① EC2 인스턴스를 고르고 띄운다 (CPU·메모리 크기 결정)
② OS 패치, JDK 설치, 보안 그룹 설정
③ JAR 올리고 systemd 등록
④ 트래픽이 늘면? → 인스턴스 추가 + 로드밸런서
⑤ 새벽에 요청이 0건이어도 → 서버는 켜져 있고 요금은 나간다
```

하루에 몇 번 안 불리는 API, 가끔 몰리는 이미지 처리 같은 일에는 **①~⑤ 대부분이 낭비**입니다.

## 누가 무엇을 관리하나

| | EC2 | 컨테이너 (EKS/ECS) | **Lambda** |
|---|---|---|---|
| 내가 올리는 것 | OS 위의 모든 것 | 컨테이너 이미지 | **함수 코드** |
| OS·런타임 패치 | 나 | 이미지는 나 | **AWS** |
| 스케일링 | 직접 설정 (ASG) | 직접 설정 (HPA 등) | **자동** (요청 수만큼) |
| 요청 0건일 때 요금 | 나감 | 나감 (노드가 떠 있음) | **0** |
| 최대 실행 시간 | 무제한 | 무제한 | **15분** |
| 상태 보관 | 가능 | 가능 | **불가** (어디서 실행될지 모름) |

> 위로 갈수록 **자유도가 높고**, 아래로 갈수록 **관리할 게 적습니다.** 뭐가 더 좋은 게 아니라 트레이드오프입니다.

## Lambda의 실행 모델

### 이벤트 → 실행 환경 → 핸들러

```
[ 이벤트 ]  API 요청, S3 업로드, 스케줄, 콘솔 "테스트" 버튼 ...
    │  JSON
    ▼
[ 실행 환경 ]  격리된 작은 VM (Firecracker microVM)
    │          - 런타임(java21) + 내 코드
    │          - 메모리 설정값만큼 할당
    ▼
handleRequest(input, context)  → 반환값이 응답
```

**Lambda에 들어오는 건 전부 JSON 이벤트**입니다. 누가 호출했는지(API Gateway, S3, 콘솔)에 따라 **JSON 모양만 다릅니다.**

### 실행 환경은 재사용된다

```
요청 1 ─▶ [환경 뜸: Init] → 핸들러 실행          ← 콜드 스타트 (느림)
요청 2 ─▶              → 핸들러 실행             ← 웜 스타트 (빠름)
요청 3 ─▶              → 핸들러 실행
  ... 한동안 요청 없음 ...
         [환경 회수]
요청 4 ─▶ [환경 뜸: Init] → 핸들러 실행          ← 다시 콜드 스타트
```

- **동시에 요청이 두 개 오면 환경이 두 개** 뜹니다. 한 환경은 한 번에 요청 하나만 처리합니다.
- 그래서 **"스레드풀"을 걱정할 필요가 없고**, 대신 **동시 실행 수**가 스케일의 단위가 됩니다.
- 재사용되니까 **static 필드에 만든 객체(DB 커넥션, SDK 클라이언트)는 다음 요청에서도 살아 있습니다.** 하지만 **언제 회수될지 모르니 믿으면 안 됩니다.** → [05 콜드 스타트](05-콜드-스타트와-snapstart.md)

## 과금

```
요금 = 요청 수 × 요청당 단가
     + 실행 시간(ms) × 메모리(GB)      ← "GB-초"
```

**메모리를 크게 잡으면 단가는 오르지만, CPU도 같이 늘어서 빨리 끝나** 총액이 비슷하거나 오히려 줄기도 합니다. → [05](05-콜드-스타트와-snapstart.md)

## 제약 — 이걸 모르면 설계가 틀어진다

| 제약 | 값 | 의미 |
|---|---|---|
| 최대 실행 시간 | **15분** | 오래 걸리는 배치는 Lambda에 안 맞음 |
| 메모리 | 128MB ~ 10GB | CPU는 메모리에 비례해서 따라옴 |
| `/tmp` 디스크 | 기본 512MB | 요청 사이에 남을 수도, 사라질 수도 있음 |
| 상태 | **없음** | 다음 요청이 같은 환경으로 간다는 보장이 없음 → 상태는 S3·DB에 |
| API Gateway 경유 시 | 기본 **29초** 응답 제한 | Lambda Timeout을 15분으로 해도 HTTP 쪽이 먼저 끊김 |

## 흔한 오해

| 오해 | 실제 |
|---|---|
| "서버리스 = 서버가 없다" | 서버는 있다. **내가 안 보이고 안 만질 뿐** |
| "요청마다 새 JVM이 뜬다" | 아니다. **환경이 재사용**되고, 새로 뜨는 건 콜드 스타트일 때뿐 |
| "Lambda가 항상 더 싸다" | 트래픽이 **꾸준히 많으면** EC2·컨테이너가 더 쌀 수 있다 |
| "static 변수에 값 저장하면 공유된다" | 환경마다 따로다. 환경이 두 개면 값도 두 벌 |
