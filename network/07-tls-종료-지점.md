# TLS 종료 지점 — 어디서 암호를 푸는가

> 한 줄 요약
> **TLS를 앞단에서 끊으면 인증서 관리와 내용 기반 라우팅이 쉬워지고, 대신 그 뒤 구간은 평문이 된다.**

## TLS 종료(termination)란

클라이언트와 서버 사이의 암호화 연결을 **어느 지점에서 풀어서 평문으로 만드느냐**의 문제다. 보통 로드밸런서나 리버스 프록시(ALB, Nginx)에서 끊는다.

```
[클라이언트] --HTTPS--> [ALB] --HTTP--> [애플리케이션 서버]
                          ↑ 여기서 종료
```

## 앞단에서 끊는 이유

**① 인증서를 한 곳에서만 관리한다.**
뒤에 서버가 몇 대든 인증서 발급·갱신은 앞단 한 번이면 된다. 서버마다 인증서를 넣으면 대수만큼 갱신 작업이 늘어난다.

**② 앞단이 요청 내용을 볼 수 있어야 판단할 수 있다.**
경로별 라우팅, 헤더 기반 분기, 캐싱은 **요청 내용을 읽어야** 가능하다. 암호화된 채로는 안이 안 보여서 L7 판단을 할 수 없다. L7 로드밸런서가 TLS를 끊는 이유가 이것이다.

## 대가 — 뒷구간은 평문

앞단부터 뒤까지는 암호화되지 않는다. 그래서 **그 구간이 신뢰할 수 있는 네트워크여야** 한다. 같은 VPC의 프라이빗 서브넷처럼 외부에서 들여다볼 수 없는 구간이면 이 전제가 성립한다.

## 세 가지 방식 비교

| 방식 | 어디서 푸는가 | 특징 |
|---|---|---|
| **TLS Termination** | 앞단에서 풀고 뒤는 평문 | 가장 흔함. L7 기능 사용 가능 |
| **TLS Passthrough** | 안 풀고 그대로 뒤로 전달 | 종단 간 암호화. 앞단은 L4로만 동작 |
| **Re-encryption (End-to-End)** | 앞단에서 풀고 **다시 암호화**해서 전달 | 규제 환경. 비용과 지연이 늘어남 |
