# NAT 동작 원리 — 커넥션 추적

> 한 줄 요약
> **나가는 패킷의 출발지 주소를 NAT 장비의 주소로 바꿔 내보내고, 돌아온 응답을 원래 보낸 쪽으로 되돌려 주는 것.**

## 왜 필요한가

사설 IP는 인터넷에서 라우팅되지 않는다. 사설 IP를 출발지로 그대로 내보내면 **응답이 돌아올 길이 없다.** 그래서 NAT이 자기 공인 주소로 갈아 끼워서 내보낸다.

```
내부: 10.0.1.5 → 나갈 때 출발지를 3.3.3.3으로 교체 → 인터넷
```

## 핵심 — 응답을 누구에게 줄지 어떻게 아는가

**NAT은 연결 하나하나를 표로 기록해 둔다.** 이것이 커넥션 추적(connection tracking) 테이블이다.

| 내부 주소:포트 | 변환된 포트 | 목적지 |
|---|---|---|
| 10.0.1.5:51000 | 3.3.3.3:40001 | 142.250.x.x:443 |
| 10.0.1.6:51000 | 3.3.3.3:40002 | 142.250.x.x:443 |

응답이 오면 이 표를 보고 원래 내부 주소로 되돌려 준다. 여러 서버가 **같은 포트 번호로 동시에 나가도, 변환 포트를 다르게 배정해서 구분**한다.

> 리눅스에서는 이 표를 `nf_conntrack`이 관리하고, 크기는 `net.netfilter.nf_conntrack_max`로 정해진다.

## 운영에서 부딪히는 세 가지

**① 표에는 한계가 있다.**
동시 연결이 아주 많아지면 표가 꽉 차서 **새 연결이 실패**한다. 이때 증상은 "느려짐"이 아니라 "일부 연결만 안 됨"이라 원인을 찾기 어렵다.

**② 기록은 시간이 지나면 지워진다.**
응답을 되돌리려면 기록이 살아 있어야 하는데, 통신이 없으면 일정 시간 뒤 표에서 제거된다. 그래서 **오래 열어두고 가끔만 쓰는 연결은 조용히 끊긴다.** 주기적으로 신호(keepalive)를 보내야 유지된다.

**③ 나가는 방향만 열린다.**
표에 기록이 생기는 시점이 "내부에서 나갈 때"뿐이다. 밖에서 먼저 들어오는 패킷은 되돌릴 대상이 없어 **원리상 전달할 수 없다.** 프라이빗 서브넷이 안전한 이유가 이것이다.

## 자주 하는 실수

- **규칙의 인터페이스 이름을 하드코딩** — `iptables` 규칙에 `-o eth0`처럼 적었는데 실제 인터페이스가 `ens5`면, **규칙은 정상 등록되지만 어떤 패킷에도 매칭되지 않는다.** 에러가 나지 않아 발견이 늦다. 이름은 동적으로 조회해서 채우는 편이 안전하다.
- **커널의 IP 포워딩을 안 켬** — `net.ipv4.ip_forward=1`이 없으면 패킷을 전달하지 않는다.
- **설정을 명령으로만 적용** — 재부팅하면 사라진다. 부팅 시 적용되는 형태(서비스 유닛, `sysctl.d`)로 남겨야 한다.
