# 네트워크 기초 — OSI부터 방화벽까지

## OSI 7계층
```
보낼 때: 7 → 1 (캡슐화: 계층마다 헤더 포장을 덧씌움)
받을 때: 1 → 7 (역캡슐화: 포장을 하나씩 벗겨냄)
```
- 편지를 겹겹이 포장(보낼 때) → 바깥부터 뜯음(받을 때)이라 순서가 반대.

| 계층 | 이름 | 핵심 | 데이터 단위 |
|---|---|---|---|
| 7 | 응용 | HTTP(S), SSH, FTP, DNS | 데이터 |
| 6 | 표현 | 포맷/암호화(SSL/TLS), 압축 | 데이터 |
| 5 | 세션 | 통신 세션 수립·복구 (소켓, API) | 데이터 |
| 4 | 전송 | 신뢰성/포트 (TCP/UDP, 포트번호) | 세그먼트(TCP)/데이터그램(UDP) |
| 3 | 네트워크 | 라우팅 (라우터, IP) | 패킷 |
| 2 | 데이터링크 | LAN 내 전달 (MAC, 스위치) | 프레임 |
| 1 | 물리 | 전기신호(0,1) (랜선, 광케이블) | 비트 |

## 데이터 단위 정리
- **패킷(Packet)**: 3계층에서 IP 헤더가 붙은 데이터 단위.
- **데이터그램(Datagram)**: 4계층에서 **UDP**일 때의 이름(TCP는 세그먼트).
- **IP**: 데이터 단위가 아니라 3계층의 **프로토콜(규약)** 이름.
  - **IP(프로토콜)** = 주소 표기·라우팅 규약 자체 / **IP 주소** = 그 규약에 따라 부여된 구체적 주소값. (같은 IP, 문맥 차이)

## TCP vs UDP (4계층)
| | TCP (등기우편) | UDP (엽서) |
|---|---|---|
| 연결 | 먼저 연결(핸드셰이크) | 그냥 바로 보냄 |
| 도착 확인 | 확인 응답(ACK) | 확인 안 함 |
| 유실 시 | 재전송 | 그냥 없어짐 |
| 속도 | 느림 | 빠름 |
| 용도 | 웹/파일/이메일(정확성) | 게임/화상통화/DNS(속도) |
- 포트가 "어디로"라면, TCP/UDP는 "어떻게 배달할지(성격)".

## 세션 계층 개념
- **세션**: 통신 시작~끝까지의 "하나의 대화 단위"(전화 통화 한 번).
- **소켓(Socket)**: 통신 창구(전화기). "IP 주소 + 포트 번호" 조합.
- **API**: 소켓/세션을 다루기 위해 OS가 제공하는 함수들(`socket()`, `connect()` 등).

## 핸드셰이크 (TCP 3-way vs TLS)
```
1. TCP 3-way 핸드셰이크 (연결 통로 열기): SYN → SYN-ACK → ACK
   ↓
2. TLS 핸드셰이크 (암호화 준비): 인증서 검증 + 암호화 키 교환
   ↓
3. 암호화된 HTTPS 데이터 전송
```
- **TCP 핸드셰이크**: 연결 자체를 맺음(모든 TCP 통신).
- **TLS 핸드셰이크**: 신원 확인+암호화 준비(HTTPS 등 암호화 시). TCP 연결 후 진행.

## NIC (Network Interface Card)
- 네트워크 통신을 담당하는 인터페이스. **물리적**(랜카드) 또는 **가상**(소프트웨어)일 수 있음.
- 물리 NIC 없이도 가상 NIC로 통신 가능. **어떤 형태든 NIC가 있어야 네트워크 통신 가능.**
| 종류 | 예시 |
|---|---|
| 물리 NIC | `eth0`, `ens33` |
| 가상 NIC | `lo`(loopback), `docker0`, `tun0`(VPN) |
- 이름 `ens33` = "ethernet network slot" (물리 위치 기반 예측 가능한 이름).
- **이더넷(Ethernet)**: NIC 이름이 아니라 유선 통신 **표준 방식**. `eth0`의 `eth`가 여기서 옴.

## IP 주소 vs MAC 주소
- **MAC 주소**: 기기(NIC)에 새겨진 고유값, 고정(주민등록번호).
- **IP 주소**: DHCP로 동적 할당 가능(호텔 방 번호).
- **IP 새로 받는 타이밍**: 처음 연결, 임대(lease) 만료·갱신 실패, 다른 네트워크 이동, 수동 갱신.
  - "매번 다름"이 아니라 "바뀔 가능성 있음"(같은 네트워크면 대개 같은 IP 유지).

## 게이트웨이 (Default Gateway)
- 자신의 네트워크 밖으로 패킷을 보내주는 **라우터의 IP 주소**.
- **패킷**: 개별 데이터 조각. **트래픽**: 패킷들의 전체 흐름/양(도로의 교통량).

## ip 명령어 (link / addr / route)
```bash
ip link show        # 인터페이스 자체 (UP/DOWN, MAC)
ip addr show        # 인터페이스의 IP 주소
ip route show       # 라우팅 테이블 (경로 규칙)
sudo ip link set ens33 up/down   # 특정 NIC 활성/비활성
```
| 객체 | 다루는 것 | 비유 |
|---|---|---|
| link | 인터페이스 자체(켜짐/MAC) | 문 자체 |
| addr | 인터페이스의 IP | 문에 붙은 주소 팻말 |
| route | 목적지별 경로 규칙 | 집 안 이정표 |

- `default via 192.168.1.1 dev eth0`:
  - `default`: 특별 규칙 없는 모든 목적지
  - `via 192.168.1.1`: 게이트웨이 경유
  - `dev eth0`: 나갈 때 사용할 인터페이스(장치)

## ip vs nmcli
- **`ip link show`**: 커널과 직접 통신, 저수준 정보(상태/MAC/MTU).
- **`nmcli device show`**: NetworkManager(데몬)를 통한 고수준 정보(IP/게이트웨이/DNS/프로필).
- systemd↔systemctl과 같은 "데몬↔CLI 도구" 구조.

## 방화벽: iptables vs UFW
- **iptables**: 커널 내장 방화벽/패킷 필터링 저수준 도구(강력하지만 복잡).
- **UFW** (Uncomplicated Firewall): iptables를 쉽게 제어하는 인터페이스("복잡하지 않은" 방화벽).
```bash
sudo ufw allow 22            # UFW (간단)
# iptables -A INPUT -p tcp --dport 22 -j ACCEPT  (복잡)
```
- **iptables vs 라우팅 테이블**: iptables=보안 검문(허용/차단), route table=길찾기(경로 결정). 완전히 다른 목적.

## netplan / cloud-init (Ubuntu 서버)
- **`/etc/netplan/*.yaml`**: 실제 네트워크 설정 내용(IP/게이트웨이/DNS). netplan이 읽어서 적용.
  - 민감 정보라 `chmod 600`(소유자만 rw). 실행 파일이 아니라 실행 권한 불필요.
- **`/etc/cloud/cloud.cfg.d/99-disable-network-config.cfg`**: cloud-init에게 "네트워크 설정 건드리지 마"라고 지시.
  - 없으면 재부팅 시 cloud-init이 수동 설정을 덮어쓸 수 있음.
