**NOT NULL**

**UNIQUE**

**PRIMARY KEY - AUTO\_INCREMENT**

**FOREIGN KEY - 참조 무결성 (부모 테이블의 값만 자식도 가질 수 있다)**



CHECK - 도메인(값의 범위) 설정할 때



제약조건 선언시 primary key하면 not null, unique 선언 안해도 됨. 하지만 not null은 하는게 관행



foreign key -> 대부분 1:n관계 만들때 씀



FOREIGN\_KEY(칼럼이름) PREFERENCES 부모테이블(부모테이블의 PK) ON DELETE RULE



부모테이블의 PK 대신에 UNIQUE 칼럼 들어올 수 있음

ON DELETE - 부모 객체가 삭제되면

ON UPDATE - 부모 객체의 ID가 변경되면 (이런 경우는 거의 없음)



RULE의 종류

RESTRICT 삭제취소 - 회원이 삭제될때 방문기록이 있다면 회원탈퇴 못함

CASCADE 함께삭제 - 회원 삭제될때 방문기록도 함께 삭제됨

**SET NULL 참조로 NULL로 변경 - 회원 삭제될때 방문기록은 남지만, 방문 기록의 FK는 다 NULL이 됨**

**=> 자식의 FK가 NULL = "아무것도 참조 안 함"**

# 트랜잭션

작업!

서로 다른 연산을 묶어서 하나의 작업으로 취급하는 것

커밋 되기 전까지는 가저장 상태임. 롤백 가능

근데 커밋 되고 나서부터는 롤백 불가능



원자성 -> 0아니면 1 - 트랜잭션으로 묶인 작업이 db에 모두 반영되던가, 반영 0이던가

일관성 -> 트랜잭션 도중 db가 변경되어도, 변경된 것이 아닌 트랜잭션시 참조한 db기준으로 진행됨

격리성 -> lock 을 건다! 나만 작업할 수 있고 다른 트랜잭션이 방해 못함.

지속성 > 커밋(트랜잭션 성공)후 db에 영구적으로 반영



커밋이란 해당 트랜잭션을 db에 영구 반영하겟다는 의미

롤백이란 마지막 커밋 상태로 돌아감



ddl문은 트랜잭션의 롤백 대상이아니다!!!!!!
