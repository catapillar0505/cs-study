# 객체 탐지 — 신뢰도 임계값과 NMS

> 한 줄 요약
> **신뢰도 임계값은 "이걸 탐지로 볼 것인가", NMS의 IoU 임계값은 "겹친 것 중 뭘 남길 것인가". 서로 다른 값이다.**

## 신뢰도 임계값 (confidence threshold)

모델은 탐지 결과마다 **"이것이 대상일 확률"** 을 함께 내놓는다. 그중 **몇 이상만 탐지로 인정할지**를 정하는 값이다.

| 임계값 | 결과 |
|---|---|
| **높게** (0.6) | 확실한 것만 잡음 → **오탐(false positive) 감소, 미탐(false negative) 증가** |
| **낮게** (0.3) | 놓치는 건 줄지만 → **오탐 증가** |

정밀도(precision)와 재현율(recall)의 트레이드오프다. 일반적으로는 오탐이 사용자 경험을 해치므로 높게 잡는 쪽을 선호한다.

## 그러나 두 실수의 무게는 상황마다 다르다

**어느 쪽 실수가 더 비싼지**를 먼저 정해야 임계값을 정할 수 있다.

| 상황 | 어느 쪽이 더 비싼가 | 임계값 |
|---|---|---|
| 일반 검색·추천 | 오탐(엉뚱한 결과)이 더 거슬림 | 높게 |
| 안전·의료 경보 | **미탐(놓침)이 치명적** — 사용자가 놓쳤다는 사실 자체를 모름 | **낮게** |
| 자동 처리(사람 확인 없음) | 오탐이 그대로 실행됨 | 높게 |

오탐은 사용자가 한 번 더 확인하면 회복되지만, **미탐은 회복 기회 자체가 없다.** 그래서 "기술적으로 최적인 값"과 "이 사용자에게 맞는 값"이 다를 수 있다.

## NMS (Non-Maximum Suppression)

같은 대상에 박스가 여러 개 잡히는 경우가 있다. **가장 확신이 높은 박스만 남기고, 그것과 많이 겹치는 나머지를 버리는 처리**다.

겹침 정도는 **IoU(Intersection over Union)** 로 잰다.

```
IoU = 두 박스의 교집합 넓이 / 합집합 넓이
```

| IoU 임계값 | 결과 |
|---|---|
| **낮게** | 조금만 겹쳐도 버림 → 박스가 깔끔하지만 **가까이 붙은 두 대상을 하나로 합쳐버림** |
| **높게** | 많이 겹쳐야 버림 → **하나의 대상에 박스가 여러 개** 남음 |

## 두 값을 구분해서 보기

| | 신뢰도 임계값 | NMS의 IoU 임계값 |
|---|---|---|
| 판단 대상 | 박스 하나 | 박스 **쌍**의 겹침 |
| 질문 | "이걸 탐지로 인정할까?" | "겹친 것 중 뭘 남길까?" |
| 조정 효과 | 탐지 개수 자체 | 중복 제거 강도 |

두 값은 이름이 비슷해 헷갈리기 쉽지만 **하는 일이 완전히 다르다.**
