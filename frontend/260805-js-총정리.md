## 1. 데이터 타입: 원시 타입과 참조 타입

이후 나오는 거의 모든 개념(`const`, `===`, 얕은 복사)이 여기서 파생되므로 가장 먼저 잡아야 한다.

### 두 가지 분류

| 구분 | 종류 | 변수에 저장되는 것 |
|---|---|---|
| 원시 타입 (Primitive) | `number`, `string`, `boolean`, `null`, `undefined`, `symbol`, `bigint` | **값 자체** |
| 참조 타입 (Reference) | `object`, `array`, `function` | **값이 있는 곳의 주소** |

### 핵심 차이

원시 타입은 상자에 값이 직접 들어간다. 참조 타입은 상자에 **"그 값이 사는 집 주소가 적힌 쪽지"**가 들어간다.

```js
// 원시 타입 - 값이 복사됨
let a = 10;
let b = a;
b = 20;
console.log(a);   // 10   ← 영향 없음

// 참조 타입 - 주소가 복사됨
let obj1 = { n: 10 };
let obj2 = obj1;
obj2.n = 20;
console.log(obj1.n);   // 20   ← 같은 객체를 보고 있어서 함께 바뀜

obj1 === obj2;   // true   ← 주소가 같음
```

### 참조 타입 비교의 함정

`===`는 참조 타입에서 **내용이 아니라 주소**를 비교한다.

```js
{ a: 1 } === { a: 1 };   // false   ← 내용은 같아도 다른 객체
[1, 2] === [1, 2];       // false

const x = { a: 1 };
const y = x;
x === y;                 // true    ← 같은 주소
```

내용을 비교하려면 직접 순회하거나 `JSON.stringify` 비교, lodash `isEqual` 등을 써야 한다.

## 2. 변수 선언 키워드: var, let, const

### 재선언과 재할당

- **재선언**: 같은 이름의 변수를 **다시 선언**하는 것 → `var a = 1; var a = 2;`
- **재할당**: 선언된 변수의 **값만 바꾸는 것** → `a = 2;`

| 키워드 | 재선언 | 재할당 | 스코프 | 선언 전 접근 |
|---|---|---|---|---|
| `var` | 가능 | 가능 | 함수 스코프 | `undefined` |
| `let` | 불가 | 가능 | 블록 스코프 | `ReferenceError` |
| `const` | 불가 | 불가 | 블록 스코프 | `ReferenceError` |

`const`는 재할당이 불가능하므로 **선언과 동시에 초기화**해야 한다.

```js
const a;         // SyntaxError: Missing initializer
let b;           // OK (undefined)
```

### const가 막는 것은 "재할당"뿐

`const`는 **이름표와 값의 연결**만 고정한다. 참조 타입의 내부는 자유롭게 수정 가능하다.

판별 기준: **`=` 왼쪽에 변수 이름만 덩그러니 있으면 재할당(금지), 점이나 대괄호가 붙어 있으면 내부 수정(허용).**

```js
const person = { name: "지나" };

person.name = "철수";      // 허용 - 내부 수정
person["age"] = 20;        // 허용 - 프로퍼티 추가
delete person.age;         // 허용 - 프로퍼티 삭제
person = { };              // TypeError - 재할당

const arr = [1, 2, 3];
arr.push(4);               // 허용
arr[0] = 99;               // 허용
arr.length = 0;            // 허용 (내용 전체 삭제도 가능!)
arr = [];                  // TypeError
```

내부까지 막으려면 `Object.freeze()`를 쓴다. (단, 얕은 동결이라 중첩 객체는 별도 처리 필요)

```js
const frozen = Object.freeze({ name: "지나" });
frozen.name = "철수";
frozen.name;   // "지나"   ← 조용히 무시됨 (strict mode에서는 TypeError)
```

### 실무 규칙

**기본은 `const`, 재할당이 필요할 때만 `let`, `var`는 쓰지 않는다.**

## 3. 값의 비교: == 와 ===

| 연산자 | 이름 | 동작 |
|---|---|---|
| `==` | 동등 연산자 (느슨한 비교) | 타입이 다르면 **암묵적 타입 변환(Type Coercion)** 후 비교 |
| `===` | 일치 연산자 (엄격한 비교) | 타입이 다르면 값을 보지 않고 즉시 `false` |

```js
1 == "1";      // true    ← "1"을 숫자 1로 변환
1 === "1";     // false   ← number vs string

0 == false;    // true    ← false를 0으로 변환
0 === false;   // false   ← number vs boolean

null == undefined;    // true    ← 특별 규칙
null === undefined;   // false
```

### == 의 함정 사례

```js
"" == 0;       // true
"0" == 0;      // true
"" == "0";     // false   ← 둘 다 문자열이라 변환이 일어나지 않음
[] == false;   // true    ← [] → "" → 0
null == 0;     // false   ← null은 undefined하고만 같음
NaN == NaN;    // false   ← 자기 자신과도 다름
```

### 실무 규칙

**항상 `===`, `!==`를 쓴다.** 단 하나의 관용적 예외는 null 체크다.

```js
if (value == null) { }   // null과 undefined를 한 번에 잡는 관용구
```

### 특수 케이스

```js
NaN === NaN;            // false   → Number.isNaN(x) 사용
0 === -0;               // true    → Object.is(0, -0)은 false
Object.is(NaN, NaN);    // true    → Object.is는 위 두 예외를 보정
```

## 4. falsy와 nullish

### falsy 값 8개

`if`문에서 `false`처럼 취급되는 값. **이 8개 외에는 전부 truthy.**

```js
false, 0, -0, 0n, "", null, undefined, NaN
```

주의할 truthy 값들:

```js
if ([])      { }   // 실행됨 - 빈 배열은 truthy
if ({})      { }   // 실행됨 - 빈 객체는 truthy
if ("0")     { }   // 실행됨 - 빈 문자열이 아님
if ("false") { }   // 실행됨 - 그냥 글자
```

### nullish

`null`과 `undefined` 두 가지만 가리키는 용어. **falsy(8개)의 부분집합**이다.

### == 비교에서 falsy는 세 그룹으로 나뉜다

같은 falsy끼리라고 `==`가 성립하지 않는다.

| 그룹 | 구성원 | 관계 |
|---|---|---|
| A | `false`, `0`, `-0`, `0n`, `""` | 서로 `==` true |
| B | `null`, `undefined` | 둘끼리만 `==` true |
| C | `NaN` | 자기 자신 포함 누구와도 false |

```js
null == false;   // false   ← 둘 다 falsy인데도 false
null == 0;       // false
undefined == 0;  // false
```

### === 는 부류가 아니라 값을 본다

```js
null === null;             // true   ← 같은 값이므로 true
undefined === undefined;   // true
null === undefined;        // false  ← 서로 다른 값이라 false
```

### falsy와 nullish를 구분해야 하는 이유

```js
let count = 0;

if (!count) { }              // 실행됨 - 0은 falsy → 버그 원인
if (count == null) { }       // 실행 안 됨 - 0은 값이 있는 것

const a = 0 || 10;   // 10   ← || 는 falsy 전체를 걸러냄
const b = 0 ?? 10;   // 0    ← ?? 는 nullish만 걸러냄
```

기본값을 넣을 때는 `??`가 안전한 경우가 많다.

## 5. 복사: 얕은 복사와 깊은 복사

1장의 "참조 타입은 주소로 저장된다"의 직접적인 결과다.

### 얕은 복사 (Shallow Copy)

`...` 스프레드, `Object.assign`, `Array.prototype.slice` 등은 **1단계만** 새로 만든다. 중첩된 객체는 주소만 복사되어 원본과 공유된다.

```js
const original = { name: "Tom", info: { city: "서울" } };
const copy = { ...original };

copy.name = "Jane";
original.name;          // "Tom"   ← 1층은 독립적

copy.info.city = "부산";
original.info.city;     // "부산"  ← 2층부터는 공유됨
original.info === copy.info;   // true
```

원시 타입은 값 자체가 복사되므로 항상 안전하다. 객체·배열만 문제가 된다.

### 깊은 복사 (Deep Copy)

```js
const deep = structuredClone(original);          // 표준 (권장)
const deep2 = JSON.parse(JSON.stringify(original));  // 함수·undefined·Date 손실 주의
// lodash: _.cloneDeep(original)
```

## 6. 스코프와 스코프 체인

### 스코프 = 변수가 유효한 범위

| 종류 | 범위 | 해당 키워드 |
|---|---|---|
| 전역 스코프 | 어디서나 | - |
| 함수 스코프 | `function` 내부 | `var` |
| 블록 스코프 | 중괄호 `{ }` 내부 | `let`, `const` |

```js
function test() {
  if (true) {
    var a = 1;
    let b = 2;
  }
  console.log(a);   // 1                 ← var는 if 블록을 벗어남
  console.log(b);   // ReferenceError     ← let은 블록에 갇힘
}

for (var i = 0; i < 3; i++) { }
console.log(i);     // 3   ← for문이 끝나도 살아있음

for (let j = 0; j < 3; j++) { }
console.log(j);     // ReferenceError
```

### 객체 리터럴은 스코프가 아니다

스코프를 만드는 것은 **함수와 블록**뿐이다. `{ }`처럼 생겼어도 객체 리터럴은 스코프를 만들지 않는다. (10장의 화살표 함수 `this` 문제의 원인)

### 스코프 체인

내부 스코프에서 변수를 찾지 못하면 **바깥 스코프로 올라가며** 탐색한다. 전역까지 갔는데도 없으면 `ReferenceError`.

```js
const global = "전역";

function outer() {
  const outerVar = "외부";
  function inner() {
    console.log(outerVar);   // 자기한테 없음 → outer에서 찾음
    console.log(global);     // outer에도 없음 → 전역에서 찾음
  }
  inner();
}
```

방향은 **안에서 밖으로만** 가능하다. 바깥에서 안쪽 변수는 볼 수 없다.

## 7. 호이스팅과 TDZ

### 자바스크립트는 코드를 두 단계로 실행한다

1. **준비 단계(생성)**: 스코프 내 선언을 훑어 메모리에 등록
2. **실행 단계**: 코드를 위에서부터 실행

선언이 위로 끌어올려진 것처럼 보이는 현상을 **호이스팅**이라 한다.

### 키워드별 준비 단계 동작

| 선언 | 준비 단계에서 | 선언 전 접근 시 |
|---|---|---|
| `var` | 등록 + `undefined`로 초기화 | `undefined` |
| `let` / `const` | 등록만, 초기화 안 함 | `ReferenceError` |
| 함수 선언문 | **함수 전체**가 등록됨 | 정상 호출 가능 |
| 함수 표현식 | `var`/`let` 규칙을 따름 | `TypeError` 또는 `ReferenceError` |

### TDZ (Temporal Dead Zone, 일시적 사각지대)

`let`/`const`도 **호이스팅은 된다.** 다만 값이 채워지지 않은 채 "접근 금지" 상태로 등록되며, 실제 선언문에 도달해야 해제된다. 이 구간이 TDZ다.

### 대표 예제

```js
console.log(a);
var a = 10;

foo();
function foo() { console.log("Hello"); }

bar();
var bar = function () { console.log("World"); };

// 출력: undefined → "Hello" → TypeError: bar is not a function
```

준비 단계 이후 실제로 실행되는 코드:

```js
var a;                                    // undefined
function foo() { console.log("Hello"); }  // 통째로 올라옴
var bar;                                  // undefined

console.log(a);     // undefined
a = 10;
foo();              // "Hello"
bar();              // TypeError - undefined에 괄호를 붙임
bar = function () { console.log("World"); };
```

### 왜 let/const를 쓰면 ReferenceError로 통일되는가

`var`는 상자가 열리기는 하므로 **그 뒤 동작에 따라 결과가 갈린다** (출력하면 `undefined`, 호출하면 `TypeError`). `let`/`const`는 **상자를 여는 단계에서 차단**되므로 뒤 동작을 볼 기회조차 없어 항상 `ReferenceError`다.

### ReferenceError vs TypeError

```js
console.log(hello);   // ReferenceError - 그런 이름이 아예 없음
var bar; bar();       // TypeError - 이름은 있으나 그 값으로 못 할 짓을 함
```

## 8. 함수의 세 가지 형태

### 함수는 값이다

자바스크립트에서 함수는 숫자나 문자열처럼 **값으로 취급**된다. 변수에 담고, 객체 프로퍼티로 넣고, 인자로 넘길 수 있다. 이를 **일급 객체(First-class Object)**라 한다.

### 함수 선언문

```js
function foo() { }
//  ↑       ↑
// 키워드   이름
```

`function`은 함수 이름이 아니라 **"함수를 만든다"는 키워드**다. `var`와 같은 예약어. 전체가 호이스팅된다.

### 함수 표현식

```js
const bar = function () { };        // 익명 함수를 값으로 대입
const baz = function named() { };   // 기명 함수 표현식 (드묾)
```

값 자리에 오므로 이름을 생략할 수 있다. 변수 선언 규칙을 따르므로 **선언 전 호출 불가**.

### 화살표 함수

```js
const arrow = () => { };
const short = x => x * 2;     // 인자 하나면 괄호 생략, 한 줄이면 return 생략
```

일반 함수와의 차이:

- 자신만의 `this`가 없다 (10장)
- `arguments` 객체가 없다
- `new`로 호출할 수 없다 (생성자가 될 수 없다)
- `prototype` 프로퍼티가 없다

### 객체 메서드 축약형

객체 프로퍼티에 들어간 함수를 **메서드**라 한다.

```js
const obj = {
  a: 10,                 // 키 + 값(숫자)
  b: function () { },    // 키 + 값(함수)  - 원래 형태
  c() { },               // 키 + 값(함수)  - ES6 축약형, b와 동일
  d: () => { }           // 키 + 값(화살표) - 축약 불가
};
```

`c() { }`는 `: function`이 생략된 것이다. 함수 이름이 축약된 게 아니라 **애초에 익명 함수였고, 키워드가 사라진 것**이다.

## 9. 콜백 함수와 고차 함수

### 콜백 함수

다른 함수에 **인자로 넘겨져서, 나중에 대신 실행되는 함수**.

```js
setTimeout(function () { console.log("띵동"); }, 1000);
//         └────── 인자1: 콜백 ──────┘       └인자2: 시간┘
```

### 왜 함수로 감싸야 하는가

괄호 `()`는 **"지금 실행하라"**는 명령이다. 실행을 미루려면 함수라는 껍데기로 감싸야 한다.

```js
setTimeout(console.log("띵동"), 1000);   // 즉시 실행되고 결과값(undefined)이 전달됨
setTimeout(() => console.log("띵동"), 1000);   // 실행되지 않은 채 전달됨

function ding() { console.log("띵동"); }
setTimeout(ding, 1000);     // 괄호 없음 = 함수 자체를 넘김
setTimeout(ding(), 1000);   // 괄호 있음 = 지금 실행해버림
```

### 콜백을 받는 대표적인 API

```js
button.addEventListener("click", () => { });   // 이벤트 발생 시
[1, 2, 3].forEach(n => console.log(n));        // 각 요소마다
[1, 2, 3].map(n => n * 2);                     // 각 요소를 변환
fetch(url).then(res => res.json());            // 응답 도착 시
```

콜백을 인자로 받거나 함수를 반환하는 함수를 **고차 함수(Higher-order Function)**라 한다.

## 10. this 바인딩

### 일반 함수: 호출 시점에 결정된다

`this`는 함수를 **정의할 때가 아니라 호출할 때** 정해진다. 기본 규칙은 **"호출 시 점(`.`) 앞에 있는 것"**.

```js
const obj = { name: "Alice", foo() { console.log(this.name); } };

obj.foo();                 // "Alice"   ← 점 앞이 obj

const detached = obj.foo;
detached();                // undefined ← 점 앞에 아무도 없음 → 전역

const other = { name: "Bob", foo: obj.foo };
other.foo();               // "Bob"     ← 점 앞이 other
```

### 바인딩 4가지 규칙 (우선순위 순)

| 규칙 | 형태 | this |
|---|---|---|
| `new` 바인딩 | `new Foo()` | 새로 생성되는 인스턴스 |
| 명시적 바인딩 | `foo.call(obj)`, `foo.apply(obj)`, `foo.bind(obj)` | 지정한 객체 |
| 암시적 바인딩 | `obj.foo()` | 점 앞의 객체 |
| 기본 바인딩 | `foo()` | 전역 객체 (strict mode에서는 `undefined`) |

```js
function greet(greeting) { console.log(greeting + ", " + this.name); }
const user = { name: "지나" };

greet.call(user, "안녕");        // 인자를 나열
greet.apply(user, ["안녕"]);     // 인자를 배열로
const bound = greet.bind(user);  // this가 고정된 새 함수를 반환
bound("안녕");
```

### 화살표 함수: 작성 위치에 따라 결정된다

화살표 함수는 **자신만의 `this`를 만들지 않는다.** 그래서 스코프 체인을 타고 올라가 **상위 스코프의 `this`를 그대로 사용**한다. 이를 렉시컬 `this`라 한다.

```js
const obj = {
  name: "Alice",
  foo: function () { console.log(this.name); },   // "Alice"
  bar: () => { console.log(this.name); }          // undefined
};
```

`bar`가 `undefined`인 이유: **객체 리터럴은 스코프가 아니므로**(6장) `bar`의 상위 스코프는 `obj`가 아니라 **전역**이다.

### 화살표 함수가 유용한 경우

콜백 안에서 `this`가 끊기는 문제를 해결한다.

```js
const timer = {
  name: "타이머",
  start: function () {
    setTimeout(function () {
      console.log(this.name);   // undefined - setTimeout이 호출하므로 점 앞이 없음
    }, 1000);
  },
  startFixed: function () {
    setTimeout(() => {
      console.log(this.name);   // "타이머" - startFixed의 this를 물려받음
    }, 1000);
  }
};
```

### 실무 규칙

**객체의 메서드는 일반 함수(축약형), 메서드 내부의 콜백은 화살표 함수.**

## 11. 클로저

### 정의

**함수와 그 함수가 선언된 렉시컬 환경(Lexical Environment)의 조합.**

렉시컬 환경이란 "그 함수가 태어난 자리에서 접근 가능한 변수들의 목록"이다.

### 외부 함수가 끝나도 변수가 살아남는다

```js
function makeCounter() {
  let count = 0;
  return function () {
    count++;
    return count;
  };
}

const counter = makeCounter();   // makeCounter는 여기서 실행 종료
counter();   // 1
counter();   // 2
counter();   // 3
```

**실행 컨텍스트는 사라지지만, 변수가 담긴 렉시컬 환경은 남는다.** 내부 함수가 `count`를 참조하고 있는 한 가비지 컬렉터(GC)가 수거하지 못하기 때문이다. GC의 판단 기준은 **"이 값을 가리키는 참조가 남아 있는가"** 하나다.

### 활용 1: 변수 은닉과 캡슐화

```js
function createAccount() {
  let balance = 1000;   // 외부에서 직접 접근 불가
  return {
    deposit(amount) { balance += amount; },
    getBalance() { return balance; }
  };
}

const account = createAccount();
account.deposit(500);
account.getBalance();      // 1500
account.balance;           // undefined - 직접 접근 불가
account.balance = 999999;  // 새 프로퍼티가 생길 뿐, 실제 balance는 그대로
account.getBalance();      // 1500
```

### 활용 2: 반복문에서의 클로저

```js
for (var i = 0; i < 3; i++) {
  setTimeout(() => console.log(i), 0);   // 3, 3, 3
}

for (let i = 0; i < 3; i++) {
  setTimeout(() => console.log(i), 0);   // 0, 1, 2
}
```

`var`는 함수 스코프라 `i`가 하나뿐이고 콜백이 실행될 때는 이미 3이 되어 있다. `let`은 반복마다 새로운 블록 스코프와 새로운 `i`가 생성되어 각각의 클로저가 따로 만들어진다.

### 주의: 메모리 누수

참조가 남아 있으면 GC가 수거하지 못하므로, 불필요해진 클로저는 참조를 끊어야 한다.

```js
let counter = makeCounter();
counter = null;   // 참조를 끊어야 count도 수거됨
```

## 12. 비구조화 할당

### 기본 개념

`=` 왼쪽에 `[ ]` 또는 `{ }` 모양을 써서, 오른쪽 값을 **모양에 맞춰 쪼개 담는다.** 왼쪽의 대괄호는 배열이 아니라 **분해 설계도**다.

```js
const [a, b] = [1, 2, 3];
// 위 한 줄 = 아래 두 줄
// const a = 1;
// const b = 2;
```

선언과 대입이 동시에 일어나므로 별도의 `a = 1` 코드는 필요 없다.

### 배열: 위치 기준

```js
const [x, y] = [10, 20];          // x=10, y=20
const [, second] = [10, 20];      // second=20 (앞자리 건너뛰기)
const [p = 5] = [];               // p=5 (기본값)
let m = 1, n = 2;
[m, n] = [n, m];                  // 두 변수 값 교환
```

### 객체: 키 이름 기준

```js
const { name, age } = { age: 20, name: "Tom" };   // 순서 무관
const { name: userName } = { name: "Tom" };       // userName="Tom" (이름 바꿔 받기)
const { city = "서울" } = { };                     // city="서울" (기본값)
const { info: { city } } = { info: { city: "부산" } };   // 중첩 구조 분해
```

### 함수 매개변수에서

```js
function printUser({ name, age = 0 }) {
  console.log(name, age);
}
printUser({ name: "지나", age: 25 });
```

## 13. Spread와 Rest

같은 `...` 기호지만 **위치에 따라 정반대로 동작한다.**

### 위치가 역할을 결정하는 이유

- **값을 주는 쪽**(`=` 오른쪽, 함수 호출 인자): 이미 값이 있음 → 펼치는 것 말고 할 게 없음 → **Spread**
- **값을 받는 쪽**(`=` 왼쪽, 매개변수 선언): 아직 값이 없음 → 모아 담는 것 말고 할 게 없음 → **Rest**

### Spread (전개) — 하나를 여럿으로

```js
const arr = [1, 2, 3];

[...arr];                    // [1, 2, 3]
[0, ...arr, 4];              // [0, 1, 2, 3, 4]
Math.max(...arr);            // Math.max(1, 2, 3)과 동일
{ ...obj, extra: 1 };        // 객체 병합
[...".. 문자열"];             // 문자열도 펼쳐짐 (이터러블이면 가능)
```

### Rest (나머지) — 여럿을 하나로

```js
const [first, ...others] = [1, 2, 3, 4];   // first=1, others=[2,3,4]
const { a, ...restProps } = obj;           // a를 제외한 나머지 전부
function func(...args) { }                 // 인자 전부를 배열로 (가변 인자)
```

앞에서 이름 붙여 가져간 것을 **제외한 나머지**를 모으므로 **항상 마지막에만** 올 수 있다.

```js
const [...rest, last] = arr;   // SyntaxError
```

### 용어 정리

정식 명칭은 **Spread Syntax(전개 구문)** 와 **Rest Element / Rest Parameter**다. "Rest 연산자"라는 정식 용어는 없으며, `...`은 배열 리터럴·객체 리터럴·함수 호출·비구조화 패턴에 붙어서만 의미를 갖는다.

```js
const rest = ...arr;   // SyntaxError - 단독으로는 쓸 수 없음
```

### Spread는 얕은 복사다

```js
const arr2 = [...arr1];        // 1단계만 복사 (5장 참고)
```

user?.profile?.name       // 중간이 null/undefined면 에러 대신 undefined

const name = "지나";

## 15. 프로토타입과 상속

### 왜 필요한가

같은 종류의 객체를 여러 개 만들 때 동일한 메서드가 중복 생성되는 낭비를 막기 위해, **공용 메서드를 한 곳에 두고 모두가 참조**하게 한다.

### [[Prototype]] 내부 슬롯

모든 객체는 **부모 역할을 하는 객체를 가리키는 링크**를 갖는다. 이것이 `[[Prototype]]` 내부 슬롯이다. (`__proto__`로 접근 가능하나 비표준 레거시이므로 `Object.getPrototypeOf()` 권장)

```js
const parent = { greet() { console.log("안녕"); } };
const child = { name: "지나" };
Object.setPrototypeOf(child, parent);

child.name;      // "지나"  ← 자신이 보유
child.greet();   // "안녕"  ← 프로토타입에서 찾아옴
```

### 프로토타입 체인

프로퍼티를 찾지 못하면 `[[Prototype]]` 링크를 따라 **위로 올라가며** 탐색한다. 최상위는 `Object.prototype`이고 그 위는 `null`이다. 끝까지 없으면 `undefined`.

```
arr = [1, 2, 3]
  ↓
Array.prototype     (push, map, filter ...)
  ↓
Object.prototype    (hasOwnProperty, toString ...)  ← 최상위
  ↓
null
```

```js
const arr = [1, 2, 3];
arr.push(4);          // arr 자신엔 없음 → Array.prototype에서 찾음
arr.hasOwnProperty;   // Object.prototype에서 찾음
arr.없는거;            // undefined
```

### 스코프 체인과의 비교

| | 찾는 대상 | 올라가는 방향 | 결정 기준 |
|---|---|---|---|
| 스코프 체인 | 변수 | 바깥 스코프로 | 코드가 **어디에 작성**되었나 |
| 프로토타입 체인 | 프로퍼티 | 부모 객체로 | 객체가 **어떻게 생성**되었나 |

### 자기 것과 상속받은 것 구분

```js
arr.hasOwnProperty("length");   // true  - 자신의 프로퍼티
arr.hasOwnProperty("push");     // false - 상속받은 것
"push" in arr;                  // true  - 체인 전체에서 검색
```

## 16. 생성자 함수와 new

### 인스턴스

`new`로 생성된 개별 객체를 **인스턴스**라 한다. 생성자 함수가 틀이고, 인스턴스가 그 틀로 찍어낸 결과물이다.

```js
function Dog(name) {
  this.name = name;              // 인스턴스마다 다른 값 → this에
}
Dog.prototype.bark = function () {   // 공유할 메서드 → prototype에
  console.log(this.name + ": 멍멍");
};

const dog1 = new Dog("코코");
const dog2 = new Dog("초코");

dog1.bark();               // "코코: 멍멍"
dog1.bark === dog2.bark;   // true - 함수는 메모리에 하나뿐
```

### new가 하는 일 4단계

```js
const dog1 = new Dog("코코");

// 내부적으로 벌어지는 일
// 1. 빈 객체 생성
const obj = {};
// 2. [[Prototype]]을 생성자의 prototype 프로퍼티에 연결
Object.setPrototypeOf(obj, Dog.prototype);
// 3. this를 그 객체로 바인딩하여 함수 실행
Dog.call(obj, "코코");
// 4. 객체를 자동 반환
return obj;
```

10장의 `new` 바인딩과 15장의 프로토타입 연결이 여기서 동시에 일어난다.

### new를 빠뜨리면

자바스크립트에서 생성자 함수는 특별한 종류의 함수가 아니라, **`new`를 붙여 호출하면 생성자로 동작할 뿐**이다.

```js
const a = new Dog("코코");   // Dog { name: "코코" }
const b = Dog("코코");        // undefined, 전역이 오염됨
```

그래서 생성자 함수는 **첫 글자를 대문자로** 쓰는 관례가 있다. `class`는 `new` 없이 호출하면 에러를 내주므로 더 안전하다.

### instanceof

```js
dog1 instanceof Dog;      // true - 프로토타입 체인에 Dog.prototype이 있는지 확인
[] instanceof Array;      // true
```

## 17. class는 문법적 설탕

ES6의 `class`는 **새로운 상속 메커니즘이 아니라**, 프로토타입 기반 상속을 읽기 쉽게 쓰기 위한 **문법적 설탕(Syntactic Sugar)**이다.

```js
class Dog {
  constructor(name) { this.name = name; }
  bark() { console.log(this.name + ": 멍멍"); }
  static info() { }              // 인스턴스가 아닌 클래스 자체의 메서드
  #secret = "비공개";             // 진짜 private 필드 (ES2022)
}

typeof Dog;                      // "function"  ← 클래스가 아니라 함수!
Dog.prototype.bark;              // 메서드는 여기에 저장됨
Object.getPrototypeOf(new Dog()) === Dog.prototype;   // true
```

### 상속

```js
class Puppy extends Dog {
  constructor(name, age) {
    super(name);                 // 부모 생성자 호출 (this 사용 전 필수)
    this.age = age;
  }
  bark() {
    super.bark();                // 부모 메서드 호출
    console.log("(작게)");
  }
}
```

### class와 생성자 함수의 차이

- `new` 없이 호출하면 `TypeError`
- 메서드는 열거되지 않음 (non-enumerable)
- 항상 strict mode로 동작
- 호이스팅은 되지만 TDZ가 적용됨 (선언 전 사용 불가)

내부 동작은 여전히 프로토타입 기반이라는 점이 핵심이다.

## 18. 이벤트 루프

### 등장인물

| 구성 요소 | 소속 | 역할 |
|---|---|---|
| Call Stack | JS 엔진 | 실행 중인 함수가 쌓이는 유일한 작업대 |
| Heap | JS 엔진 | 객체가 저장되는 메모리 공간 |
| Web API | 브라우저 / Node | 타이머, 네트워크 등을 대신 처리 |
| Task Queue | 브라우저 / Node | 완료된 콜백이 대기하는 줄 |
| Event Loop | 브라우저 / Node | 스택이 비면 큐에서 꺼내 올림 |

**"자바스크립트는 싱글 스레드"란 엔진이 싱글 스레드라는 뜻**이다. 브라우저 자체는 멀티 스레드이므로 타이머를 세는 동안에도 엔진은 다른 코드를 실행할 수 있다. `setTimeout`, `fetch`, `DOM`은 ECMAScript 명세가 아닌 **런타임이 제공하는 기능**이다.

### 동작 순서

```js
console.log("1");
setTimeout(() => console.log("2"), 1000);
console.log("3");
// 출력: 1, 3, 2
```

1. 엔진이 `setTimeout` 호출 → 브라우저에 **콜백과 시간을 함께** 전달
2. 브라우저가 콜백을 보관하고 타이머 시작, 엔진은 즉시 다음 줄로
3. 시간이 되면 **브라우저가** 콜백을 태스크 큐에 넣음
4. 이벤트 루프가 **콜 스택이 완전히 빈 것**을 확인하고 콜백을 꺼냄
5. 엔진이 콜백을 실행

### 우선순위: 마이크로태스크가 먼저다

큐는 두 개이며, **마이크로태스크 큐의 우선순위가 더 높다.**

```
콜 스택이 빔
  ↓
마이크로태스크 큐 → 전부 비울 때까지 실행 (실행 중 추가된 것까지)
  ↓
매크로태스크 큐 → 딱 하나만 꺼냄
  ↓
다시 마이크로태스크 확인 (반복)
```

| 매크로태스크 | 마이크로태스크 |
|---|---|
| `setTimeout`, `setInterval` | `Promise.then/catch/finally` |
| 이벤트 콜백, I/O | `queueMicrotask` |
| `setImmediate` (Node) | `process.nextTick` (Node) |

```js
console.log("1");
setTimeout(() => console.log("2"), 0);
Promise.resolve().then(() => console.log("3"));
console.log("4");
// 출력: 1, 4, 3, 2
```

### setTimeout의 시간은 보장되지 않는다

```js
setTimeout(() => console.log("1초 뒤"), 1000);
const start = Date.now();
while (Date.now() - start < 5000) { }
// 출력은 5초 뒤
```

브라우저는 1초 시점에 정확히 큐에 넣었지만, 콜 스택이 비지 않아 꺼내가지 못한 것이다. **`setTimeout(fn, n)`은 "n밀리초 뒤 실행"이 아니라 "n밀리초 뒤 대기줄에 세움"**이며, 실제 실행은 그 이후 스택이 빌 때다.

`setTimeout(fn, 0)`은 "즉시"가 아니라 **"현재 작업이 모두 끝난 직후"**를 의미한다.

### 콜 스택을 막으면 안 되는 이유

콜 스택이 점유된 동안에는 클릭 처리, 화면 갱신, 애니메이션이 **전부 멈춘다.** 무거운 작업은 잘게 쪼개거나 Web Worker로 분리해야 한다.

## 19. Promise와 async await

### 콜백 지옥

비동기 작업을 콜백으로 중첩하면 가독성이 급격히 나빠진다.

```js
getUser(id, (user) => {
  getPosts(user, (posts) => {
    getComments(posts[0], (comments) => { });
  });
});
```

### Promise

비동기 작업의 **미래 결과를 담는 객체**. `pending` → `fulfilled` 또는 `rejected` 상태를 갖는다.

```js
const promise = new Promise((resolve, reject) => {
  if (성공) resolve(값);
  else reject(에러);
});

promise
  .then(value => { })      // 성공 시
  .catch(err => { })       // 실패 시
  .finally(() => { });     // 성공/실패 무관하게
```

`then`은 새 Promise를 반환하므로 **체이닝**이 가능하고, 이것으로 콜백 중첩이 평평해진다.

```js
getUser(id)
  .then(user => getPosts(user))
  .then(posts => getComments(posts[0]))
  .catch(err => console.error(err));
```

`then` 콜백은 **마이크로태스크 큐**에 등록된다(18장).

### 병렬 처리

```js
Promise.all([p1, p2, p3]);         // 모두 성공해야 성공, 하나라도 실패하면 즉시 실패
Promise.allSettled([p1, p2, p3]);  // 성공/실패 무관하게 전부 기다림
Promise.race([p1, p2]);            // 가장 먼저 끝난 것 하나
Promise.any([p1, p2]);             // 가장 먼저 성공한 것 하나
```

### async / await

Promise를 **동기 코드처럼 보이게** 쓰는 문법.

```js
async function load() {            // async 함수는 항상 Promise를 반환
  try {
    const user = await getUser(id);      // Promise가 끝날 때까지 대기
    const posts = await getPosts(user);
    return posts;
  } catch (err) {                        // 에러는 try-catch로 처리
    console.error(err);
  }
}
```

주의: `await`는 **직전 작업이 끝나야 다음이 시작**되므로, 서로 무관한 작업은 `Promise.all`로 병렬 처리하는 것이 빠르다.

```js
// 순차 - 느림
const a = await taskA();
const b = await taskB();

// 병렬 - 빠름
const [a, b] = await Promise.all([taskA(), taskB()]);
```

## 면접 빈출 한 줄 정리

| 주제 | 핵심 |
|---|---|
| `var` vs `let`/`const` | 스코프(함수 vs 블록), 재선언 여부, TDZ 유무 |
| `const`의 의미 | 재할당 금지일 뿐, 참조 타입 내부는 수정 가능 |
| `==` vs `===` | 암묵적 타입 변환 여부. 실무는 `===` |
| falsy 8개 | `false 0 -0 0n "" null undefined NaN` |
| 호이스팅 | 선언이 준비 단계에 등록됨. `var`는 `undefined` 초기화, `let`/`const`는 TDZ |
| 함수 선언문 vs 표현식 | 선언문은 전체 호이스팅, 표현식은 변수 규칙을 따름 |
| 클로저 | 함수 + 선언된 렉시컬 환경. 외부 함수 종료 후에도 변수 유지 |
| `this` | 일반 함수는 **호출 시점**, 화살표 함수는 **작성 위치**의 상위 `this` |
| 얕은 복사 | Spread는 1단계만. 깊은 복사는 `structuredClone` |
| 프로토타입 | 프로퍼티를 못 찾으면 체인을 따라 위로. 최상위는 `Object.prototype` |
| `class` | 프로토타입 기반의 문법적 설탕. `typeof`는 `"function"` |
| 이벤트 루프 | 동기 → 마이크로태스크 전부 → 매크로태스크 하나 |

## 에러 메시지로 원인 찾기

| 에러 | 원인 | 예시 |
|---|---|---|
| `ReferenceError: x is not defined` | 이름 자체가 없거나 TDZ 구간 접근 | `console.log(a); let a = 1;` |
| `TypeError: x is not a function` | 이름은 있으나 값이 함수가 아님 | `var f; f();` |
| `TypeError: Assignment to constant variable` | `const` 재할당 | `const a = 1; a = 2;` |
| `SyntaxError: Missing initializer in const` | `const` 초기값 누락 | `const a;` |
| `SyntaxError: Identifier has already been declared` | `let`/`const` 재선언 | `let a; let a;` |
| `TypeError: Cannot read properties of undefined` | `undefined`의 프로퍼티 접근 | `obj.a.b` (a가 없을 때) |
| `TypeError: Class constructor cannot be invoked without 'new'` | `class`를 `new` 없이 호출 | `Dog()` |
