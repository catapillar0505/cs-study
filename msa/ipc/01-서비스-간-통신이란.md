# 서비스 간 통신이란

## 한 줄로

모놀리스에서 **공짜였던 메서드 호출**이 서비스를 쪼개는 순간 **네트워크를 건너는 일**이 된다. 느려지고, 실패하고, 형식과 프로토콜을 골라야 한다. 그 선택지 전부를 **IPC**라고 부른다.

## IPC라는 단어

**IPC = Inter-Process Communication (프로세스 간 통신)**

**프로세스**란 "실행 중인 프로그램 하나"입니다. 리눅스에서 `ps -ef`를 찍으면 나오는 줄 하나하나가 프로세스입니다.

같은 프로그램 안에서 함수를 부르는 것은 그냥 **메서드 호출**입니다.

```java
bankingService.transfer(...);   // 같은 JVM 안. 나노초 단위, 실패 없음
```

그런데 상대가 **다른 프로세스**(심지어 다른 서버)에 있으면 이야기가 완전히 달라집니다.

```
[ 모놀리식 ]                        [ 마이크로서비스 ]

bankingService.transfer(...)        ??? 어떻게 부르지 ???
   ↑ 그냥 메서드 호출                  ↑ 네트워크를 건너야 함
     (나노초, 실패 없음)                 (밀리초, 실패 가능)
```

네트워크를 건너야 하니 새로운 고민이 줄줄이 생깁니다.

- **어떤 형식**으로 데이터를 실어 보낼까? (사람이 읽는 JSON? 기계가 읽는 이진 데이터?)
- **어떤 프로토콜**로 보낼까? (HTTP/1.1? HTTP/2?)
- **동기**로 기다릴까, **비동기**로 던져만 놓을까?
- 상대가 **죽어 있으면** 어떻게 할까?

이 선택지들을 통틀어 **IPC 방식**이라고 부릅니다.

## 동기 vs 비동기

| | 동기(Synchronous) | 비동기(Asynchronous) |
|---|---|---|
| 동작 | 응답이 올 때까지 **기다림** | 요청만 던지고 **바로 다음 일** |
| 대표 | REST, gRPC | 메시지 큐(Kafka, RabbitMQ) |
| 장점 | 흐름이 직관적, 결과를 바로 앎 | 상대가 죽어도 내가 안 멈춤 |
| 단점 | **상대가 느리면 나도 느려짐** | 흐름 추적이 어려움, 결과를 나중에 앎 |

**이 폴더는 동기 통신만 다룹니다.**
비동기(메시지 브로커·이벤트) 쪽은 [eda](../eda/README.md)에 따로 정리되어 있습니다.

> **동기 통신의 진짜 위험**은 느려지는 게 아니라 **연쇄 장애**입니다.
> 상대가 느려지면 내 스레드가 그 응답을 기다리며 묶이고, 스레드가 다 묶이면 나도 죽습니다.
> 그 대비책이 [msa/06 장애 격리](../06-장애-격리.md)입니다.

## 동기 통신의 두 갈래

동기 통신에도 성격이 아주 다른 두 방식이 있습니다.

| | **REST (OpenFeign)** | **gRPC** |
|---|---|---|
| 데이터 형식 | **JSON** (사람이 읽는 텍스트) | **Protobuf** (기계가 읽는 이진) |
| 프로토콜 | HTTP/1.1 | **HTTP/2** |
| 규약이 어디 있나 | **문서/코드** (믿어야 함) | **`.proto` 파일** (컴파일러가 강제) |
| 오타를 언제 발견 | **런타임** (실행해봐야 앎) | **컴파일 타임** (빌드가 실패함) |
| 속도 | 상대적으로 느림 | 빠름 |
| 디버깅 | **쉬움** (curl·브라우저로 눈으로 확인) | 어려움 (이진이라 눈으로 못 읽음) |
| 브라우저가 직접 호출 | ✅ 가능 | ❌ 불가능 |

각각의 자세한 내용은 [02 OpenFeign](02-openfeign-선언적-http.md)과 [03 gRPC](03-grpc와-protobuf.md)에 있습니다.

## 둘 다 목표는 같다 — "원격을 로컬처럼"

형식도 프로토콜도 다르지만, **두 방식이 이루려는 것은 똑같습니다.**

```java
// OpenFeign
UserResponse user = userClient.getUser(1L);

// gRPC
StockResponse res = stockStub.checkStock(request);
```

**두 줄 다 평범한 자바 메서드 호출처럼 생겼습니다.**
하지만 그 뒤에서는 주소 찾기, 데이터 직렬화, 네트워크 전송, 응답 파싱이 전부 일어납니다.

이렇게 **원격 호출을 로컬 호출처럼 보이게 하는 것**을
**RPC(Remote Procedure Call, 원격 프로시저 호출)** 라고 부릅니다.

> 이름 그대로 "원격(Remote)에 있는 절차(Procedure)를 호출(Call)한다"입니다.
> gRPC의 `RPC`가 바로 이것이고, OpenFeign도 방식만 다를 뿐 같은 목표를 갖습니다.

## 흔한 오해

**"비동기로 바꾸면 빨라진다"**
아닙니다. 응답이 빨리 오는 게 아니라 **내가 기다리지 않을 뿐**입니다. 바뀌는 것은 속도가 아니라 **결합도**입니다.

**"gRPC가 빠르니까 무조건 gRPC를 쓰면 된다"**
