# RabbitMQ vs Kafka

## 한 줄로

메시지 하나하나를 **정확히 배달**하는 게 중요하면 RabbitMQ, 대량의 흐름을 **저장하고 재생**하는 게 중요하면 Kafka.

## 비교표

| 비교 항목 | RabbitMQ (AMQP) | Apache Kafka (Commit Log) |
|---|---|---|
| **본질** | 큐 (메시지 배달) | 로그 (이벤트 저장) |
| **핵심 사상** | 신뢰성 있는 배달 + 복잡한 라우팅 | 초고속 대용량 스트리밍의 영속적 보존 |
| **소비 방식** | Push (브로커가 전송) | Pull (컨슈머가 Polling) |
| **소비 후 상태** | 즉각 삭제 (Ack 시 제거) | 지정 기간 디스크 보존 (**재소비 가능**) |
| **처리량** | 초당 수만 건 | **초당 수백만 건** |
| **순서 보장 범위** | 단일 큐 내부 | 동일 파티션 내부 |
| **라우팅** | **매우 유연** (Exchange 3종) | 단순 (토픽만) |
| **운영 난이도** | 낮음 | 높음 |
| **적합 유스케이스** | 이메일/알림 발송, 업무 동기화, 복잡한 라우팅 | 행동 로그 추적, 메트릭 분석, 이벤트 소싱 |

## 선택 기준 한 문장

> 메시지 하나하나를 **정확히 배달**하는 게 중요하면 RabbitMQ,
> 대량의 흐름을 **저장하고 재생**하는 게 중요하면 Kafka.
