# gateway — API 게이트웨이

서비스가 여러 개로 늘어났을 때 **모든 요청이 지나는 단일 관문**을 두는 이야기입니다.
클라이언트가 주소 하나만 알면 되게 만들고, 인증·로깅·요청 제한 같은 **공통 관심사를 한곳에서** 처리합니다.

## 한눈에 보는 요청 한 번

```
  클라이언트
     │  GET /delivery/status
     ▼
┌──────────────────────────────────────────────────────┐
│ API Gateway                                          │
│                                                      │
│  ① 조건(Predicate) 검사   "이 경로가 내 라우트인가?"  │
│  ② 목적지 결정            lb://DELIVERY-SERVICE       │
│  ③ 필터들이 차례로 실행                                │
│       · 경로 재작성   /delivery/status → /status      │
│       · 헤더 주입     X-Gateway-Source 추가           │
│       · 로깅                                          │
│       · 인증 검사     실패하면 401, 여기서 끝 ❌       │
│       · 요청 제한     초과하면 429, 여기서 끝 ❌        │
│  ④ 서비스 명부에서 실제 주소를 골라 전송               │
└──────────────────────────────────────────────────────┘
     │
     ▼
  백엔드 서비스 (자기 도메인 로직만 갖고 있음)
```

## 이 폴더를 관통하는 한 문장

> **모든 요청이 반드시 게이트웨이를 지나므로, 공통 검사는 거기서 한 번만 한다.**
> 필터는 **다음으로 넘기는 함수를 부르면 통과, 안 부르면 차단**이다.
