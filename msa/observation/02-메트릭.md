# 메트릭 (Metrics)

## 한 줄로

**일정 간격으로 수집되는 숫자**다. 개별 사건이 아니라 **"지금 몇 개, 얼마나 걸림"** 같은 집계값을 다루므로 저장이 싸고 오래 보관할 수 있다.

## 기초 — 시계열 데이터란

**시계열(Time-series) 데이터**는 **"시각 + 값"의 쌍이 시간 순으로 쌓인 것**입니다.

```
14:00:00   CPU 사용률 32%
14:00:15   CPU 사용률 35%
14:00:30   CPU 사용률 71%     ← 여기서 무슨 일이?
14:00:45   CPU 사용률 88%
```

**로그와 무엇이 다른가**

| | **로그** | **메트릭** |
|---|---|---|
| 담는 것 | **사건 하나하나의 서술** ("주문 1234가 실패했다") | **집계된 숫자** ("실패 횟수 = 37") |
| 크기 | 큼 (문장, 스택 트레이스) | **아주 작음** (숫자 몇 개) |
| 보관 기간 | 짧음 (며칠~몇 주) | **김** (몇 달~몇 년) |
| 답하는 것 | "무슨 일이 있었나" | **"얼마나 / 몇 번 / 몇 초"** |

**메트릭이 싼 이유**: 요청이 100만 건 와도 **"100만"이라는 숫자 하나**만 저장하면 되기 때문입니다.
그래서 **오래 두고 추세를 볼 수 있습니다.** "지난달 같은 요일보다 응답이 느려졌나?" 같은 질문이 가능해집니다.

## 기초 — 메트릭의 세 가지 종류

메트릭은 **성격에 따라 세 종류**로 나뉩니다. 이 구분을 모르면 도구를 쓸 수 없습니다.

### ① Counter (카운터) — 계속 늘어나기만 하는 수

```
요청 수:  0 → 15 → 42 → 108 → 250 ...
```

**절대 줄지 않습니다.** (앱을 재시작하면 0으로 초기화될 뿐입니다.)

**비유: 자동차 주행거리계.** 총 몇 km 달렸는지만 올라갑니다.

> **누적값 자체는 별로 안 궁금합니다.** "지금까지 요청 250만 건"은 별 의미가 없죠.
> 진짜 궁금한 건 **"초당 몇 건이냐"** 입니다. 그건 **기울기(변화율)** 로 계산합니다.
> → [03의 `rate()`](03-prometheus와-grafana.md)

### ② Gauge (게이지) — 오르내리는 현재 값

```
메모리 사용량:  1.2GB → 1.8GB → 1.4GB → 2.1GB ...
```

**비유: 자동차 속도계·연료계.** 지금 이 순간의 값이고, 올라가기도 내려가기도 합니다.

예: 메모리 사용량, 활성 스레드 수, DB 커넥션 점유 수, 큐에 쌓인 메시지 수

### ③ Timer / Histogram (타이머·히스토그램) — 걸린 시간의 분포

**"이 API가 얼마나 걸렸나"** 를 재는 것인데, 단순히 시간 하나를 저장하지 않습니다.

**왜 평균만 보면 안 되는가 — 평균의 함정**

```
요청 100건의 응답 시간:
  99건은 10ms,  1건은 10,000ms

평균 = (99×10 + 10000) / 100 = 109ms
```

**"평균 109ms네, 괜찮구먼"** 하고 넘어가지만, 실제로는 **한 명의 사용자가 10초를 기다렸습니다.**

그래서 **백분위수(percentile)** 를 봅니다.

| 지표 | 뜻 |
|---|---|
| **p50 (중앙값)** | 절반의 요청은 이보다 빠르다 |
| **p95** | **100명 중 95명은 이보다 빠르다** = 나머지 5명이 겪는 최악 |
| **p99** | 100명 중 99명은 이보다 빠르다 |

> **실무에서는 p95·p99를 봅니다.** 서비스가 커질수록 "1%"가 하루에 수만 명이 되기 때문입니다.
> 자세히는 → [performance/01 p95와 백분위수](../../performance/01-p95와-백분위수.md)

그래서 Timer는 시간을 **구간(bucket)별로 몇 건씩 들어왔는지** 세어 둡니다. 그게 **히스토그램**입니다.

```
0~10ms   : ████████████████ 84건
10~50ms  : ████ 12건
50~100ms : █ 3건
100ms~   : ▌1건            ← 이 꼬리가 p99 를 만든다
```

## 기초 — 태그(Tag / Label)

같은 메트릭이라도 **어떤 조건에서의 값인지** 나눠 보고 싶습니다.

```
http.server.requests                       ← 그냥 "요청 수"
http.server.requests{uri="/orders", status="200"}   ← "주문 API 의 성공 요청 수"
http.server.requests{uri="/orders", status="500"}   ← "주문 API 의 실패 요청 수"
```

**태그(Prometheus에서는 라벨)** 는 메트릭에 붙는 **꼬리표**입니다.
이 덕분에 "어느 API가, 어떤 상태로" 같은 **쪼개 보기(drill-down)** 가 가능합니다.

> ⚠️ **태그 값의 종류가 너무 많으면 안 됩니다.**
> `uri="/orders/1"`, `/orders/2`, `/orders/3` … 처럼 **ID를 태그에 넣으면** 시계열이 무한히 늘어나
> 저장소가 터집니다. 이를 **카디널리티 폭발(cardinality explosion)** 이라고 합니다.
> 그래서 Spring은 URI를 `/orders/{id}` 처럼 **패턴으로 정규화**해서 태그에 넣습니다.

## Spring Boot Actuator

**Actuator(액추에이터)** 는 **애플리케이션 내부 상태를 HTTP로 꺼내 볼 수 있게 열어주는 기능 모음**입니다.

> **단어 뜻**: actuator = "작동기, 구동 장치". 기계 내부를 조작·점검하는 장치에서 온 이름입니다.

의존성 하나만 넣으면 이런 것들이 생깁니다.

| 엔드포인트 | 보여주는 것 |
|---|---|
| `/actuator/health` | 애플리케이션이 살아 있는가, DB 연결은 되는가 |
| `/actuator/metrics` | 수집 중인 메트릭 목록과 값 (JSON) |
| `/actuator/prometheus` | **Prometheus가 읽어갈 형식**으로 전체 메트릭 |
| `/actuator/env` | 환경 변수·설정값 전부 |
| `/actuator/threaddump` | 지금 스레드들이 뭘 하고 있는지 |

### ⚠️ 기본적으로 거의 다 닫혀 있습니다

**보안 때문입니다.** `/actuator/env`는 환경 변수를 전부 보여주므로 **DB 비밀번호가 노출될 수 있습니다.**

그래서 기본으로는 `/health` 정도만 열려 있고, **필요한 것만 명시적으로 열어야** 합니다.

```yaml
management:
  endpoints:
    web:
      exposure:
        include: health, metrics, prometheus     # 이 셋만 연다
```

> **"Prometheus 연동했는데 404가 난다"** 는 십중팔구 이 설정을 안 한 것입니다.
>
> 반대로 **`include: "*"` 로 전부 여는 것은 운영에서 절대 금물**입니다.
> 운영에서는 Actuator를 **별도 포트로 분리**하고 방화벽 안쪽에서만 접근하게 하는 것이 정석입니다.

## Micrometer

**Micrometer(마이크로미터)** 는 **계측 도구의 표준 인터페이스** 역할을 합니다.

```
       내 코드
          │  "요청 수를 하나 올려줘"  (표준 API 로 호출)
          ▼
   ┌──────────────┐
   │  Micrometer  │   ← 파사드(껍데기)
   └──────┬───────┘
          │  실제 전송은 아래 중 무엇이든
   ┌──────┼───────┬──────────┬─────────┐
   ▼      ▼       ▼          ▼         ▼
Prometheus  Datadog  CloudWatch  New Relic  ...
```

**이게 왜 좋은가?** 나중에 모니터링 도구를 Prometheus에서 Datadog으로 바꿔도
**애플리케이션 코드를 한 줄도 안 고쳐도 됩니다.** 의존성만 바꾸면 됩니다.

> **파사드(Facade)** 는 "건물 정면"이라는 뜻으로, **뒤에 뭐가 있든 앞모습은 똑같이 보이게 하는 층**입니다.
> **로깅의 SLF4J와 정확히 같은 구조입니다.** SLF4J로 코드를 짜두면 Logback이든 Log4j든 갈아끼울 수 있죠.
> Micrometer는 흔히 **"메트릭 계의 SLF4J"** 라고 불립니다.

### Observation API — 메트릭과 추적을 하나로

Spring Boot 3부터는 한 걸음 더 나갑니다.

**한 번의 "관측(Observation)"을 선언하면, 거기서 메트릭과 분산 추적이 동시에 나옵니다.**

```
   [ 하나의 Observation ]  "주문 처리"
            │
     ┌──────┴───────┐
     ▼              ▼
  메트릭          Span
 (몇 번, 몇 초)  (추적 타임라인의 한 구간)
```

예전에는 메트릭용 코드와 추적용 코드를 **따로** 심어야 했습니다. 이제는 **한 번만** 심으면 됩니다.
[04 분산 추적](04-분산-추적.md)과 [05 OpenTelemetry](05-opentelemetry.md)가 이 위에서 돌아갑니다.

## 자동으로 잡히는 주요 메트릭

Actuator를 넣기만 하면 **아무 코드도 안 짜도** 이만큼이 수집됩니다.

| 카테고리 | 대표 메트릭 | 주요 태그 | 무엇을 보나 |
|---|---|---|---|
| **JVM 메모리** | `jvm.memory.used` | `area:heap` | Heap 사용량, **메모리 누수 탐지** |
| **스레드** | `jvm.threads.live`<br>`jvm.threads.virtual.*` | — | 플랫폼 스레드·**가상 스레드** 상태 |
| **시스템** | `system.cpu.usage`<br>`process.cpu.usage` | — | 호스트·컨테이너 CPU 사용량 |
| **HTTP** | `http.server.requests` | `uri`, `status`, `method` | **엔드포인트별 지연 시간과 에러율** ★ |
| **DB 커넥션** | `hikaricp.connections.active` | `pool` | **커넥션 풀 점유율·고갈 위험** |

> **`http.server.requests`가 가장 많이 쓰입니다.** Timer 타입이라
> **요청 수·총 소요 시간·최댓값**이 한꺼번에 잡히고, `uri`와 `status` 태그로 쪼개 볼 수 있습니다.
>
> **`hikaricp.connections.active`도 실무에서 중요합니다.**
> 커넥션 풀이 마르면 응답이 느려지는데, CPU·메모리는 멀쩡해 보여서 원인을 놓치기 쉽습니다.
> → [msa/06 장애 격리](../06-장애-격리.md)의 스레드 풀 고갈과 같은 이야기입니다.

## 직접 계측하기 — 비즈니스 메트릭

자동 수집은 **기술 지표**만 잡습니다. **"주문이 몇 건 성공했나"** 같은 건 직접 심어야 합니다.

가장 간단한 방법은 메서드에 어노테이션 하나를 붙이는 것입니다.

```java
@Timed(value = "api.hello.latency", description = "Hello API 응답 지연 시간 및 호출 횟수")
@GetMapping("/hello")
public String hello(...) { ... }
```

이러면 메트릭 세 개가 자동으로 생깁니다.

| 생성되는 메트릭 | 뜻 |
|---|---|
| `api_hello_latency_seconds_count` | **누적 호출 횟수** (Counter) |
| `api_hello_latency_seconds_sum` | **누적 소요 시간 합** |
| `api_hello_latency_seconds_max` | **최대 지연 시간** |

> **평균을 따로 저장하지 않는 이유**: `sum ÷ count` 로 언제든 계산할 수 있기 때문입니다.
> 이렇게 **원재료만 저장하고 계산은 조회 시점에** 하는 것이 시계열 DB의 방식입니다.

> ⚠️ **`@Timed`는 AOP로 동작합니다.** 그래서 이를 처리해 줄 빈(`TimedAspect`)을 등록해야 하고,
> **같은 클래스 안에서 자기 메서드를 부르면(self-invocation) 동작하지 않습니다.**
> → [msa/06의 AOP 프록시 함정](../06-장애-격리.md)과 같은 이야기입니다.
