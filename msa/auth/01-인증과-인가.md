# 인증과 인가

## 한 줄로

**인증은 "너 누구야?", 인가는 "너 이거 해도 돼?"** 다. 서비스를 쪼개면 모놀리스에서 쓰던 **세션 방식이 무너지므로**, 서버가 아무것도 기억하지 않는 **토큰 방식**으로 옮겨간다.

## 두 단어부터 구분하기

| | 인증 (Authentication, **AuthN**) | 인가 (Authorization, **AuthZ**) |
|---|---|---|
| 질문 | **"너 누구야?"** | **"너 이거 해도 돼?"** |
| 예 | 아이디·비밀번호 확인, 토큰 검증 | 관리자만 삭제 가능 |
| 실패 시 | **401** Unauthorized | **403** Forbidden |

**401과 403의 차이**는 실무에서 자주 헷갈립니다.

```
401 = "너 누군지 모르겠다"        (토큰이 없거나, 만료됐거나, 위조됨)
403 = "누군지는 알겠는데, 권한이 없다"  (로그인은 했지만 관리자가 아님)
```

> 이름이 헷갈리게 지어졌습니다. `401 Unauthorized`는 이름과 달리 **인증(authentication) 실패**입니다.
> 표준 이름이 잘못 붙은 유명한 사례이니, **숫자와 뜻으로 외우는 편**이 낫습니다.

## 모놀리식 시절의 방법 — 세션

```
① 로그인 성공 → 서버 메모리에 "sessionId=abc123 → 홍길동" 저장
② 브라우저에 쿠키로 sessionId=abc123 전달
③ 이후 요청마다 쿠키를 보냄 → 서버가 메모리를 뒤져 "아, 홍길동이구나"
```

**서버가 하나일 땐 완벽합니다.** 서버가 "누가 로그인했는지"를 기억하고 있으니까요.

이렇게 **서버가 상태(누가 로그인했는지)를 들고 있는 방식**을 **Stateful**이라고 합니다.

## MSA에서 세션이 무너지는 이유

```
   요청 ─┬─▶ [product-service #1]  메모리: abc123 → 홍길동 ✅
         └─▶ [product-service #2]  메모리: (비어있음) → 누구세요? ❌
```

- 서버를 여러 대로 늘리면 **세션이 공유되지 않습니다**
- 서비스가 20개면 **20개가 전부 세션 저장소를 봐야** 합니다
- 서버를 재시작하면 **로그인이 전부 풀립니다**

> 세션을 Redis 같은 외부 저장소로 빼면 공유는 됩니다(**Spring Session**).
> 하지만 요청마다 그 저장소를 조회해야 하고, 저장소가 죽으면 전체가 멈춥니다.

## 해결 — 토큰 방식 (Stateless)

발상을 뒤집습니다. **서버가 기억하지 말고, 클라이언트가 증명서를 들고 다니게 하자.**

```
① 로그인 성공 → 서버가 "홍길동, 관리자, 3월 2일 만료" 라고 적고 [서명]한 종이를 줌
② 이후 요청마다 그 종이를 헤더에 담아 보냄
③ 서버는 아무것도 저장하지 않음. 서명만 확인하면 내용을 믿을 수 있음
```

**서버가 상태를 갖지 않으므로(Stateless) 몇 대로 늘리든 상관없습니다.**

**"서명"이 핵심입니다.** 종이에 적힌 내용을 누가 고치면 서명이 깨지므로 바로 들통납니다.
그 "서명된 종이"가 바로 **JWT**입니다. → [02 JWT](02-jwt.md)

| | 세션 (Stateful) | 토큰 (Stateless) |
|---|---|---|
| 누가 기억하나 | **서버** | **클라이언트가 들고 다님** |
| 서버 증설 | 세션 공유 문제 발생 | **아무 문제 없음** |
| 서버 재시작 | 로그인 풀림 | 영향 없음 |
| 무효화(강제 로그아웃) | **즉시 가능** (서버에서 지우면 끝) | **어려움** (만료까지 유효) |
| 정보 크기 | 쿠키에 ID 하나 | 토큰이 커질 수 있음 |

> **토큰이 만능은 아닙니다.** "이미 발급한 토큰을 즉시 무효화하기 어렵다"는 것이 근본적인 약점입니다.
> 그래서 **액세스 토큰의 수명을 짧게(보통 5분)** 두는 관행이 생겼습니다.

## 인증을 직접 만들지 말라는 격언

로그인 기능을 직접 만들면 이 모든 걸 구현해야 합니다.

- 회원가입·로그인·로그아웃, 비밀번호 해싱, 비밀번호 재설정 메일
- 토큰 발급·갱신·폐기
- 2단계 인증(MFA), 구글·카카오 소셜 로그인 연동
- 역할·그룹 관리, 관리자 화면
- **보안 취약점 대응** (여기서 한 번 실수하면 전체가 뚫립니다)

그래서 **전문 인증 서버**에 맡깁니다. 이런 제품을 **IAM**이라고 부릅니다.

> **IAM = Identity and Access Management (인증·인가 통합 관리).**
> 대표적인 오픈소스가 **Keycloak**이고, 클라우드 서비스로는 AWS Cognito, Auth0 등이 있습니다.
> → [03 OAuth2와 Keycloak](03-oauth2와-keycloak.md)
